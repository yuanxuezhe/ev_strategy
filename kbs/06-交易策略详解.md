# 06 交易策略详解：通道偏离回撤

> 相关源码：`ChannelDeviationStrategy`（`evtrade/strategies/channel_deviation.py`；DSL body 见同文件 `_CHANNEL_DEVIATION_DSL`，git 历史原始行号对应 `mysql_analyze_demo.py:249-327`，commit 5585371）

## 1. 策略思想

均值回归型策略，在 EMA 通道（UP=EMA(H,21)，DW=EMA(L,21)）的基础上做两段式判断：

- **第一段（极端偏离，置位标记）**：价格远跑到通道外 → 记下"发生过极端偏离"（锁存，不动作）
- **第二段（回撤确认，触发信号）**：随后价格收回通道附近 → 触发买入/卖出

| 信号 | 含义 | 逻辑链 |
|---|---|---|
| **BUY** | 超跌反弹 | L 远低于下轨（low_dev > low1）→ 之后 H 回升到下轨上方/附近（low_dev_h < low2）→ 买 |
| **SELL** | 超涨回落 | H 远高于上轨（high_dev > high1）→ 之后 L 回落到上轨下方/附近（high_dev_l < high2）→ 卖 |

两段式 + 锁存 = **迟滞（hysteresis）**：触发条件必须先"走出很远"再"收回来"，单边贴着阈值抖动不会连续打信号。

## 2. 四个偏离量（全部为百分比）

设当前周期桶 H=最高价、L=最低价，通道 UP、DW（DSL body `channel_deviation.py:30-33`）：

| 变量 | 公式 | 直觉含义 | 用途 |
|---|---|---|---|
| `low_dev` | `(DW - L)/DW × 100` | L 低于下轨多少（>0 才在轨外） | 判定下轨**极端偏离** |
| `high_dev` | `(H - UP)/UP × 100` | H 高于上轨多少 | 判定上轨**极端偏离** |
| `low_dev_h` | `(DW - H)/DW × 100` | H 相对下轨的位置（H≥DW 时 ≤0） | BUY 触发：`< low2` 即 H 已收回到下轨上方或仅差一点 |
| `high_dev_l` | `(L - UP)/UP × 100` | L 相对上轨的位置（L≤UP 时 ≤0） | SELL 触发：`< high2` 即 L 已回落到上轨下方或仅差一点 |

注意方向：`low_dev_h < low2` 在 H 完全收回下轨上方时（负值）恒成立，所以该条件表达的是"整根 bar 的最高点已回到下轨附近以内"。

## 3. 默认参数

| 参数 | 默认 | CLI | 角色 |
|---|---|---|---|
| `low1` | 1.5% | `--params "low1:1.5"` | 下轨极端偏离阈值（置位） |
| `low2` | 1.0% | `--params "low2:1.0"` | 下轨回撤确认阈值（触发 BUY） |
| `high1` | 1.5% | `--params "high1:1.5"` | 上轨极端偏离阈值（置位） |
| `high2` | 0.5% | `--params "high2:0.5"` | 上轨回撤确认阈值（触发 SELL） |

> 参数经 `--params "low1:1.5;low2:1.0;high1:1.5;high2:0.5"` 一次传入（cli.py:112-115），
> 由 `_resolve_strategy_params` 按 `params_spec` 填默认 + 类型/范围校验（base.py:87-120）；
> 未声明的参数名会报错（防拼写错误）。`params_spec` 声明顺序即 DSL 的 `p0..pN` 顺序。

**硬约束：必须 low1 > low2、high1 > high2**，否则"先冲出、再收回"的迟滞结构退化，会立即置位立即触发，锁存失去意义（DSL body 注释；`params_spec` 在 channel_deviation.py:70-75）。

## 4. 状态机与锁存

每个方向两个状态位 + 一个单桶操作锁：

```
low_hit=False ──low_dev>low1──▶ low_hit=True   （置位，此后保持，哪怕偏离回落）
low_hit=True  ──low_dev_h<low2──▶ BUY, low_hit=False （触发并解除）
```

上轨对称：`high_dev>high1 → high_hit=True`；`high_hit 且 high_dev_l<high2 → SELL 并解除`。

要点（DSL body `channel_deviation.py:23-51`；`state_spec` 声明见 `channel_deviation.py:77-83`）：

1. **置位后不会被清除**：即使 low_dev 回落到 low1 以下，low_hit 仍是 True，必须等到回撤确认（low_dev_h < low2）才触发并解除——这就是"锁存"。
2. **触发基于"上一根遗留的标记"**：`check` 先用进入时的 low_hit/high_hit（即 info 里的 `*_prev`）判断触发，再处理置位。
3. **单桶单操作**（`lock_ts / low_acted / high_acted`，DSL body `channel_deviation.py:26-29`；均为 `state_spec` 声明的持久字段，**不再用下划线前缀**）：
   - 桶 ts 变化时（`ctx.cur_ts != ctx.lock_ts`）重置两个操作锁
   - 同一根周期桶内，每个方向"置位"和"触发"合计**最多发生一次**（`not ctx.low_acted` 等守卫）
   - 目的：防止桶内 H/L 大幅波动导致"置位→触发→再置位→再触发"的连环信号
4. **触发互斥**：BUY/SELL 判断是 `if / elif`，同一桶最多出一个信号。

> 持久状态字段（`low_hit/high_hit/lock_ts/low_acted/high_acted`）由策略类 `state_spec` 声明，
> 框架自动投影到 numba jitclass / CUDA device 函数 / Python ctx（见 12 号文档 2.5 节、14 号文档第 3 节）。

## 5. check() 的完整判定顺序（DSL body `channel_deviation.py:23-51`）

```
输入: 规范接口 check(cur: dict, indicators: dict) (base.py:122);
      channel_deviation.check 兼容旧 (cur, up, dw) 与新 (cur, dict) 两种调用 (channel_deviation.py:99)
1. up/dw 为 None 或 0 → 返回 (None, {})            # 指标未就绪/非法 (DSL body 第 24 行 return 0)
2. 桶 ts 变了 → 重置 low_acted/high_acted            # 新桶恢复操作资格 (lock_ts 检测)
3. 计算四个偏离量，快照 info（含 *_prev 锁存前值 + up/dw）
4. 触发段（用上一根遗留的 hit 标记）:
     low_hit 且 low_dev_h<low2 且 本桶 low 未操作  → BUY, low_hit=False, low_acted=True
   elif high_hit 且 high_dev_l<high2 且 本桶 high 未操作 → SELL, high_hit=False, high_acted=True
5. 置位段:
     low_dev>low1 且 本桶 low 未操作  → low_hit=True,  low_acted=True
     high_dev>high1 且 本桶 high 未操作 → high_hit=True, high_acted=True
返回 (signal, info)
```

返回值：`signal ∈ {"BUY","SELL",None}`；`info` 携带 `up`/`dw` 与四个偏离量 + 触发前的锁存状态（`low_hit_prev/high_hit_prev`，channel_deviation.py:130-134）；Engine 只在有信号时打印，打印行由策略 `format_signal_line` hook 生成（见第 9 节）。

## 6. 信号在何时以什么价执行

- 触发时点：**当前未闭合周期桶**的某根 1m bar 到来、且条件满足的那一刻（盘中信号，不等桶收盘）
- 执行价格：`cur["close"]` = 当前桶最新合并收盘价（即最近一根 1m bar 的 close）（DSL/引擎路径同口径）
- 回测中 `SimulatedExecutor` 以该价即时成交；对实盘意味着"信号一到就市价下单"的语义

## 7. 调参直觉

- `low1/high1` 越大：越挑剔"极端"，信号更少更逆势
- `low2/high2` 越接近 `low1/high1`：迟滞带越窄，触发越快（但也更容易在弱反弹/回落中入场）
- `high2` 默认 0.5 比 `low2` 1.0 小：SELL 的确认更贴近上轨（回落幅度要求更小），体现多空不对称
- 改参数前建议先小段日期回测，看信号行里 `low_dev/high_dev` 的实际分布再定阈值

## 8. 倍投系数 scale (2026-09-05 新增)

`--scale` (默认 1.0 = 关闭) 控制连续同方向信号的**数量累乘**：

```
首次同向信号:  数量 = trade_qty          (如 20000)
连续第 2 次:   数量 = 上一次 × scale      (scale=2 → 40000)
连续第 3 次:   数量 = 80000 ...          (乘法逐次累乘)
方向翻转:      重置回 trade_qty (卖出后, 下次买入重新从基础数量开始)
```

语义细节：
- **信号即计数**：即使某次信号因资金/持仓不足未成交（q≤0），也计入连续次数；
- 数量仍受 `min(数量, 资金/价格)`（买）与 `min(数量, 持仓)`（卖）上限保护，不会透支；
- 实现为**逐次乘法**（不用 pow），CPU/GPU 逐位一致（tests/test_gpu.py 锁定）；
- 扫描时可作为网格维度：`--grid "scale=1.0,2.0,3.0"`。

**实测教训** (513120.SH, 20250101~20260903, 同参数): scale=1 → 超额 +6.37%/回撤 6.24%;
scale=2 → 超额 +2.04%/回撤 14.85%, 成交额从 334 万涨到 893 万 (费用 ×2.7)。
倍投在该标的上放大了回撤与费用、降低超额 —— **倍投不是免费午餐, 必须进网格验证**,
且注意资金上限会让连续倍投在 3~4 次后退化成"全仓买入"。

## 9. 策略展示 hook (2026-09-08 框架去特殊化)

框架层不再假定任何指标字段名; 信号行打印与指标列拼接由策略覆写三个 hook 完成
(`StrategyBase` 定义于 base.py:126-160; channel_deviation 实现于 channel_deviation.py:137-185)：

- **`format_signal_line(cur, signal, info) -> str`**：verbose 引擎的信号 bar 打印行。
  hook 签名**无 positional 指标**; 所需字段（up/dw、偏离值、`*_prev` 锁存）从 `info` dict 自取。
  Engine 只负责 `print`，不假设 info 的键。默认实现仅打 OHLCV + 信号。
- **`get_extra_bucket_columns(*, tab, per_bar) -> dict`**：在 framework 桶表之上追加展示列
  （CLI `--show-bars` / `--bars-out` 用）。`tab` 是 `kernel.bucket_table()` 输出（OHLCV + sig + n_sig，
  **不含指标**）; `per_bar` 是 `bundle_per_bar` 打包的 per-bar 数组 dict（`per_bar["up"]`/`["dw"]`/`["h"]`/`["l"]`）。
  channel_deviation 在此拼接 4 个偏离百分比（按 `tab['count']` 桶聚合到与 `tab['ts']` 等长）。
- **`get_extra_signal_columns(*, sig, per_bar) -> dict`**：在 framework 信号轨迹之上追加 per-bar 列
  （CLI `--signals-out` 用）。framework 默认仅写 `(stime, signal)`; channel_deviation 在此追加 EMA up/dw。

> 关键变化：旧版 `bucket_table` 直接输出 EMA 上下轨 up/dw，现已移除；up/dw 改由
> `bundle_per_bar` 打包进 `per_bar` dict，策略 hook 按需取值。CLI/replay 不再出现
> `up/dw` 等指标键作为函数关键字参数（framework 去指标化，见 12 号文档 2.6 节）。
