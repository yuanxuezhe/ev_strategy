# 06 交易策略详解：通道偏离回撤

> 相关源码：`ChannelDeviationStrategy`（`evtrade/strategies/channel_deviation.py`），
> 统一策略契约 `VectorizedStrategy`（`evtrade/strategies/vectorized_base.py`）。
> 本文档为 2026-09-09 统一 CPU/GPU 重构版（DSL body 已废，全部 Python + xp）。

## 1. 策略思想

均值回归型策略，使用 **EMA 通道**（UP=EMA(H, tf1)，DW=EMA(L, tf1)）作为偏离参考。
EMA 增量状态由策略 `compute_signals_for_one_bar` 内部通过
`evtrade/indicators/ema_channel_push` / `ema_channel_current` 自维护
（`tf1` 由策略 `params_spec` 声明，默认 21）；
批量路径用 `evtrade/indicators/xp_ema_channel` 一次性算全序列（xp 算子）。

策略两段式判断：

- **第一段（极端偏离，置位标记）**：价格远跑到通道外 → 记下"发生过极端偏离"（锁存，不动作）
- **第二段（回撤确认，触发信号）**：随后价格收回通道附近 → 触发买入/卖出

| 信号 | 含义 | 逻辑链 |
|---|---|---|
| **BUY** | 超跌反弹 | L 远低于下轨（low_dev > low1）→ 之后 H 回升到下轨上方/附近（low_dev_h < low2）→ 买 |
| **SELL** | 超涨回落 | H 远高于上轨（high_dev > high1）→ 之后 L 回落到上轨下方/附近（high_dev_l < high2）→ 卖 |

两段式 + 锁存 = **迟滞（hysteresis）**：触发条件必须先"走出很远"再"收回来"，单边贴着阈值抖动不会连续打信号。

## 2. 四个偏离量（全部为百分比）

设当前周期桶 H=最高价、L=最低价，通道 UP、DW 由 `compute_signals` 内部调 `xp_ema_channel(...)` 算得：

| 变量 | 公式 | 直觉含义 | 用途 |
|---|---|---|---|
| `low_dev` | `(DW - L)/DW × 100` | L 低于下轨多少（>0 才在轨外） | 判定下轨**极端偏离** |
| `high_dev` | `(H - UP)/UP × 100` | H 高于上轨多少 | 判定上轨**极端偏离** |
| `low_dev_h` | `(DW - H)/DW × 100` | H 相对下轨的位置（H≥DW 时 ≤0） | BUY 触发：`< low2` 即 H 已收回到下轨上方或仅差一点 |
| `high_dev_l` | `(L - UP)/UP × 100` | L 相对上轨的位置（L≤UP 时 ≤0） | SELL 触发：`< high2` 即 L 已回落到上轨下方或仅差一点 |

注意方向：`low_dev_h < low2` 在 H 完全收回下轨上方时（负值）恒成立，所以该条件表达的是"整根 bar 的最高点已回到下轨附近以内"。

## 3. 默认参数

| 参数 | 默认 | CLI | 角色 |
|---|---|---|---|
| `tf1` | 21 | `--params "tf1:21"` | EMA 通道周期（策略私有，`compute_signals` 内调 `xp_ema_channel` / `ema_channel_*` 时用） |
| `low1` | 1.5% | `--params "low1:1.5"` | 下轨极端偏离阈值（置位） |
| `low2` | 1.0% | `--params "low2:1.0"` | 下轨回撤确认阈值（触发 BUY） |
| `high1` | 1.5% | `--params "high1:1.5"` | 上轨极端偏离阈值（置位） |
| `high2` | 0.5% | `--params "high2:0.5"` | 上轨回撤确认阈值（触发 SELL） |

> 参数经 `--params "tf1:21;low1:1.5;low2:1.0;high1:1.5;high2:0.5"` 一次传入（cli.py），
> 由 `_resolve_params` 按 `params_spec` 填默认 + 类型/范围校验（`vectorized_base.py`）；
> 未声明的参数名会报错（防拼写错误）。

**硬约束：必须 low1 > low2、high1 > high2**，否则"先冲出、再收回"的迟滞结构退化，会立即置位立即触发，锁存失去意义。

## 4. 状态机与锁存

每个方向两个状态位 + 一个单桶操作锁：

```
low_hit=False ──low_dev>low1──▶ low_hit=True   （置位，此后保持，哪怕偏离回落）
low_hit=True  ──low_dev_h<low2──▶ BUY, low_hit=False （触发并解除）
```

上轨对称：`high_dev>high1 → high_hit=True`；`high_hit 且 high_dev_l<high2 → SELL 并解除`。

要点（见 `channel_deviation.py::_fsm_step`）：

1. **置位后不会被清除**：即使 low_dev 回落到 low1 以下，low_hit 仍是 True，必须等到回撤确认（low_dev_h < low2）才触发并解除——这就是"锁存"。
2. **触发基于"上一根遗留的标记"**：`_fsm_step` 先用进入时的 low_hit/high_hit 判断触发，再处理置位。
3. **单桶单操作**（`lock_ts / low_acted / high_acted`，维护在 instance `_fsm` dict）：
   - 桶 ts 变化时（`cur_ts != lock_ts`）重置两个操作锁
   - 同一根周期桶内，每个方向"置位"和"触发"合计**最多发生一次**（`not low_acted` 等守卫）
   - 目的：防止桶内 H/L 大幅波动导致"置位→触发→再置位→再触发"的连环信号
4. **触发互斥**：BUY/SELL 判断是 `if / elif`，同一桶最多出一个信号。

> 持久状态字段（`low_hit / high_hit / lock_ts / low_acted / high_acted`）由策略
> 在 `__init__` 中初始化为 instance dict (`self._fsm`)；不再需要 AST 白名单 + 三端投影。

## 5. compute_signals 的完整判定顺序

### 5.1 批量路径 (vectorized_engine / sweep)

```python
def compute_signals(self, xp, bars, params):
    tf1 = int(params["tf1"])
    low1, low2, high1, high2 = (float(params[k]) for k in
                                ("low1", "low2", "high1", "high2"))

    # 1) 向量化: EMA 通道 + 4 个偏离 (xp 数组算子)
    up, dw = xp_ema_channel(xp, bars["h"], bars["l"], tf1)
    up_v = xp.where(xp.isnan(up), 0.0, up)
    dw_v = xp.where(xp.isnan(dw), 0.0, dw)
    low_dev = (dw_v - bars["l"]) / dw_v * 100.0
    high_dev = (bars["h"] - up_v) / up_v * 100.0
    low_dev_h = (dw_v - bars["h"]) / dw_v * 100.0
    high_dev_l = (bars["l"] - up_v) / up_v * 100.0

    # 2) FSM (Python 循环; cupy 时先 .get() 拉回 host)
    ts = bars["ts"]; mark = bars["mark"]
    if hasattr(ts, "get"):
        ts = ts.get(); mark = mark.get()
        low_dev_h = low_dev_h.get(); low_dev = low_dev.get()
        high_dev_l = high_dev_l.get(); high_dev = high_dev.get()

    n = len(ts)
    sig = np.zeros(n, dtype=np.int8)
    state = _init_fsm_state()
    for i in range(n):
        if mark[i] == 0:
            continue
        s = _fsm_step(state, int(ts[i]),
                      float(low_dev_h[i]), float(low_dev[i]),
                      float(high_dev_l[i]), float(high_dev[i]),
                      low1, low2, high1, high2)
        sig[i] = s
    return sig
```

### 5.2 逐 bar 路径 (Engine.on_bars / 实盘) — 子类覆写

```python
def compute_signals_for_one_bar(self, xp, bar, params):
    tf1 = int(params["tf1"])
    cur_ts = int(bar["ts"])
    cur_high = float(bar["h"])
    cur_low = float(bar["l"])

    # 桶切换 push (旧桶 high/low 闭锁入 EMA)
    if self._has_prev and self._prev_ts != cur_ts:
        us, uc, ue = self._up_st
        us, uc, ue = ema_push(us, uc, ue, self._cur_high, tf1)
        self._up_st = (us, uc, ue)
        ds, dc, de = self._dw_st
        ds, dc, de = ema_push(ds, dc, de, self._cur_low, tf1)
        self._dw_st = (ds, dc, de)

    self._prev_ts = cur_ts
    self._cur_high = cur_high; self._cur_low = cur_low
    self._has_prev = True

    # 当前通道值 (含 pending)
    us, uc, ue = self._up_st; ds, dc, de = self._dw_st
    up = ema_current(us, uc, ue, cur_high, tf1)
    dw = ema_current(ds, dc, de, cur_low, tf1)
    if up == 0.0 or dw == 0.0:
        return 0

    low_dev = (dw - cur_low) / dw * 100.0
    high_dev = (cur_high - up) / up * 100.0
    low_dev_h = (dw - cur_high) / dw * 100.0
    high_dev_l = (cur_low - up) / up * 100.0

    return _fsm_step(self._fsm, cur_ts, low_dev_h, low_dev,
                     high_dev_l, high_dev,
                     float(params["low1"]), float(params["low2"]),
                     float(params["high1"]), float(params["high2"]))
```

> **关键**: 批量路径与逐 bar 路径**共享同一个 `_fsm_step(state, ...)` 函数**,
> 保证两种入口信号 bitwise 一致 (replay/reconcile 测试锁定)。

### 5.3 规范接口 (VectorizedStrategy 基类)

`compute_signals_for_one_bar` 默认实现（framework 包装）:

```python
def compute_signals_for_one_bar(self, xp, bar, params):
    single = {k: xp.asarray([v]) for k, v in bar.items()}
    return int(self.compute_signals(xp, single, params)[0])
```

子类可在不维护 instance state 时省略覆写；本策略维护 instance EMA + FSM，所以覆写以避免 O(n²) 重算。

## 6. 信号在何时以什么价执行

- 触发时点：**桶 CLOSE**（Engine 看到 `cur.ts != last_cur.ts` 那一刻），用上一桶 finalized OHLCV 驱动策略。
- 执行价格：`prev["close"]` = 上一桶最终收盘价（即最近一根 1m bar 的 close）。批量 / 逐 bar 路径同口径。
- 回测中 `SimulatedExecutor` 以该价即时成交；对实盘意味着"信号一到就市价下单"的语义。

## 7. 调参直觉

- `low1/high1` 越大：越挑剔"极端"，信号更少更逆势
- `low2/high2` 越接近 `low1/high1`：迟滞带越窄，触发越快（但也更容易在弱反弹/回落中入场）
- `high2` 默认 0.5 比 `low2` 1.0 小：SELL 的确认更贴近上轨（回落幅度要求更小），体现多空不对称
- 改参数前建议先小段日期回测，看信号行里 `low_dev/high_dev` 的实际分布再定阈值

## 8. 倍投系数 scale

`--scale` (默认 1.0 = 关闭) 控制连续同方向信号的**数量累乘**：

```
首次同向信号:  数量 = trade_qty          (如 20000)
连续第 2 次:   数量 = 上一次 × scale      (scale=2 → 40000)
连续第 3 次:   数量 = 80000 ...          (乘法逐次累乘)
方向翻转:      重置回 trade_qty (卖出后, 下次买入重新从基础数量开始)
```

语义细节：
- **信号即计数**：即使某次信号因资金/持仓不足未成交（q≤0），也计入连续次数；
- 数量仍受 `min(数量, 资金/价格)`（买）与 `min(数量, 持仓)`（卖）上限保护，不会透支；
- 实现为**逐次乘法**（不用 pow），CPU/GPU 逐位一致（tests/test_strategy_unified.py 锁定）；
- 扫描时可作为网格维度：`--grid "scale=1.0,2.0,3.0"`。

**实测教训** (513120.SH, 20250101~20260903, 同参数): scale=1 → 超额 +6.37%/回撤 6.24%;
scale=2 → 超额 +2.04%/回撤 14.85%, 成交额从 334 万涨到 893 万 (费用 ×2.7)。
倍投在该标的上放大了回撤与费用、降低超额 —— **倍投不是免费午餐, 必须进网格验证**,
且注意资金上限会让连续倍投在 3~4 次后退化成"全仓买入"。

## 9. 策略展示 hook

框架层不再假定任何指标字段名; 信号行打印由策略覆写 `format_signal_line` 完成
(`VectorizedStrategy` 默认实现仅打 OHLCV + 信号；channel_deviation 自定义展示):

- **`format_signal_line(ts, sig, info) -> str`**：verbose 引擎的信号 bar 打印行。
  hook 签名**无 positional 指标**; 所需字段（up/dw、偏离值）从 `info` dict 自取。
  Engine 只负责 `print`，不假设 info 的键。

> **2026-09-09 变化**:
> - 删除 `get_extra_bucket_columns` / `get_extra_signal_columns` (旧 bucket_table / per-bar bundle)。
>   framework 输出列已简化为 OHLCV + sig (桶表) / `(stime, signal)` (信号轨迹)；
>   策略若需要展示列, 应在 `format_signal_line` 内一次性算 (verbose 引擎才打)。
> - 不再有 per-bar bundle 数组 (`bundle_per_bar` 已删); 策略需要展示列用 `format_signal_line` 的 info dict。
