## 2. 流式内核 (kernel.py)

### 2.1 核心思想

**"流式"是语义属性**: 每根 bar 的决策只依赖截至该 bar 的数据与状态递推。
回测批量灌入 ≠ 未来函数——内核内部仍是逐根递推。一个 `step()` 函数四种用法:

| 场景 | 用法 | 特点 |
|---|---|---|
| 实盘 | `step(state, stime, o,h,l,c,v)` 单根调用 | 真流式, 微秒级 |
| 回测 | `run_backtest(state, bar数组...)` | 内部同一 step 循环 |
| 扫描 | 每组参数一个 state, N 次 run_backtest | nogil + 线程池并行 |
| GPU | 同一步进语义移植 CUDA kernel | 见 gpu.py 草图 |

### 2.2 实现要点

- **状态** = jitclass `KernelState`, **按策略 `state_spec` 工厂化** (不再固定 ~40 标量):
  `kernel._build_kernel_state_source(strategy_name)` (kernel.py:176-330) 读策略类的 `state_spec`,
  生成 `_STATE_SPEC` + `KernelState` jitclass 源码; `core/kernel_dsl.py` 在 exec 前把它
  splice 进 `# ==== KERNEL-STATE-CLASS-BEGIN/END ====` 区间 (kernel_dsl.py:139-145)。
  基类 `KernelState` (kernel.py:333-460) 已无 state_spec 字段, 降级为返回 signal=0 的向后兼容壳。
  零堆分配; 闭合桶不保存, 只在桶切换时把 H/L 喂进 EMA 状态 (与参考 `_sync_ema` 等价)。
- **桶时间戳整数化（任意周期通用）**: `bucket_ts_encoded` 以 naive-epoch（stime 即
  北京墙钟）为锚对周期秒数取整, `compute_bucket_general` 为 datetime 参考实现。
  对老 7 周期与原字符串算法**逐例等价**; 90m/7m/3d 等任意周期详见 04 第 5 节。
  实现踩过的坑: ①不能用 `t % (value*place)` 取边界余数——会被高位字段污染;
  ②字段取整法对 >60m/3d 根本不可行, 已整体切换为 epoch 锚定算法。
- **浮点表达式与参考实现逐字一致** (`value*k + ema*(1-k)` 等), 保证逐位 (bitwise) 相同,
  阈值比较不会因精度差异翻转。
- **参考行为细节的复刻** (差分测试逼出来的等价点):
  - up/dw 无效时策略提前 return, 且**不做**桶锁重置 (参考 check 的返回位置);
    (注: 桶内的 per-bar up/dw 数组现由 `bundle_per_bar` 打包为 dict 契约传递, 见 2.5)
  - mark 跟随桶内最新一根 bar;
  - 预热期也喂 EMA (只挡策略不挡指标);
  - 参考引擎 `flush()` 的收尾回调对信号/账户无影响 (单桶锁), 内核无需复现;
  - 参考实现空数据时 flush 会 IndexError, 内核安全返回 (已知差异, 见 2.3)。
- **内核新增指标** (参考没有, 扫描选参用): 逐 bar 盯市最大回撤、成交额合计、买卖笔数。

### 2.3 策略段与 DSL 渲染 (2026-09-06 步骤 2; 2026-09-07 三端单源, 详见 14 号文档)

`_strategy_check` 的函数体位于 `# ==== DSL-STRATEGY-BEGIN/END ====` 标记之间,
**函数体为空 (占位 `pass`)**。`core/kernel_dsl.py::build_dsl_kernel(name)` 按同一标记
把任意策略的 DSL 渲染结果 (含 channel_deviation) 整段替换进去, exec 出该策略专用
的内核模块 —— 一份内核源, N 个策略特化; **所有策略同路径** (2026-09-07 重构后
channel_deviation 不再走"冻结本尊"快路, 历史特殊分支已删除)。
72 项差分测试现以 `dsl_kernel("channel_deviation")` 的特化产物与 Python ref 引擎对账。

### 2.4 与参考实现的有意差异 (仅两处)

1. 空数据: 参考实现 IndexError, 内核返回零交易。
2. `flush()` 收尾回调: 参考会多调用一次 `strategy.check` (测试可观察到 trace 多一条
   记录), 但永不产生信号、不改账户; 内核不做。交易结果完全一致。

### 2.5 state_spec: 持久状态声明与三端投影 (2026-09-08)

DSL 策略在**类**上声明 `state_spec` 描述跨桶持久的状态字段, 框架据此自动投影到三端,
**内核/gpu 不再有任何硬编码状态字段**。

- **schema** (base.py:75):
  `state_spec = {"<字段名>": {"type": bool | int | float, "default": <标量初值>}}`
  框架层 type 映射: bool → numba `boolean` / CUDA `int`; int → `int64` / `long long`;
  float → `float64` / `double` (dsl.py 的 `_PY_TYPE_TO_NUMBA` / `_PY_TYPE_TO_CUDA`)。
- **声明是强制项**: DSL 策略必须显式声明 `state_spec` (空 dict 合法 = 无持久状态, DSL body
  只能写局部变量); 缺声明编译期抛 `CompileError` (dsl.py:473-488 `_require_state_spec`)。
- **三端投影**:
  - numba jitclass → `kernel._build_kernel_state_source` 生成 `_STATE_SPEC` + `KernelState` 字段 (本节 2.2);
  - CUDA device 函数 → `dsl.build_cuda_state_decls` / `build_cuda_strategy_check_call` 注入 `{STATE_DECLS}` / `{STRATEGY_STATE_ARGS}` (见第 6 节);
  - Python ctx → `dsl.make_dsl_ctx` 按 `state_spec.default` 注入初值 (dsl.py)。
- **示例** (channel_deviation.py:77-83): `low_hit/high_hit` (bool) / `lock_ts` (int) / `low_acted/high_acted` (bool)。
- **新增持久字段无需改内核**: 在策略类 `state_spec` 加一行即可, 框架三端自动投影。

### 2.6 bucket_table / bundle_per_bar: 桶表与 per-bar dict 契约 (框架去特殊化)

框架层只输出行情 + 信号轨迹, **不计算任何指标列**; 策略专属指标由策略 hook 按需拼接。

- `kernel.bucket_table(stime, sig, ts_out, o_out, h_out, l_out, c_out, v_out)` (kernel.py:710-741):
  返回每根周期桶闭合时点的 `{"ts","open","high","low","close","volume","count","sig","n_sig"}`,
  **不含 EMA 上下轨 / 偏离百分比等指标列** (旧版曾在此输出 up/dw, 已移除)。
- `kernel.bundle_per_bar(sig, up, dw, ts_arr, o, h, l, c, v)` (kernel.py:744-762):
  把内核填充的 per-bar 数组打包为 framework 通用契约 dict:
  `{"sig": per-bar 信号轨迹, "per_bar": {"up","dw","ts","o","h","l","c","v"}}`。
  调用方 (CLI / replay) 不必逐项命名指标字段; 策略在 hook 内按需取 `per_bar["up"]` 等。
- **策略 hook 拼接指标列**: `StrategyBase.get_extra_bucket_columns(tab, per_bar)` 在桶表之上追加
  展示列 (如 4 个偏离百分比, channel_deviation.py:155-172); `get_extra_signal_columns(sig, per_bar)`
  在信号轨迹之上追加 per-bar 列 (如 EMA up/dw, channel_deviation.py:174-185)。框架不假定任何指标字段名。

## 3. 等价性保证 (差分测试)

`tests/test_differential.py`: 同一 bar 序列喂参考引擎与内核, 对比——

1. **逐 bar 信号序列** (预热偏移切片后);
2. **逐 bar UP/DW 通道值** (参考 None ↔ 内核 NaN, 其余 bitwise);
3. **逐笔成交** ts/side/qty/price (qty/price 要求 bitwise);
4. **账户终态** cash/position/last_price (bitwise) + 汇总口径。

覆盖: 全部 7 周期 + 任意周期 (7m/90m/2h/3d) × 4 组参数(含迟滞退化边界 low1=low2) ×
tf1∈{5,13,21,60,300} × 有/无预热 × 3 个随机种子 × 2.9 万根长序列。
当前 56 项测试全部通过 (含 GPU 差分与回放对账)。

## 4. 并发扫描 (sweep.py + cli)

```bash
# 真实数据 (MySQL 自动拉取并缓存 npz, 二次运行零数据库开销)
python -m evtrade sweep --code 159992.SZ --start 20250101 --end 20260903 \
    --data-cache cache \
    --grid "low1=1.0,1.5,2.0" --grid "high2=0.3,0.5,0.8" \
    --split 20250701 --workers 16 --out results.csv

# 无库体验 (合成数据)
python -m evtrade sweep --synthetic-days 120 --start 20250601 --end 20250701 \
    --grid "low1=0.4,0.6,0.8" --grid "tf1=10,21,60"

# GPU 档 (需 cupy + nvidia-*-cu12 pip 轮子, 见下节)
python -m evtrade sweep ... --device gpu
```

- 每组参数 = 一个独立 KernelState, `run_backtest` 带 `nogil=True`,
  ThreadPoolExecutor 并行, bar 数组全组共享只读。
- `--split YYYYMMDD` 输出 train_*/test_ 两套指标 (测试窗以 split 前全部数据预热、
  锁存状态全新起算), 按测试窗超额排序选参, 防止单段过拟合。
- 网格键: low1/low2/high1/high2/tf1/period/trade_qty (周期与 tf1 也是普通网格维度——
  流式内核下每组重算只要毫秒级, 无需指标预计算缓存)。
- 注意: train_n + test_n 与全窗口成交数可差分界处的锁存跨越成交 (测试窗独立起算), 属预期。

## 5. 基准实测 (本机: 32 逻辑核 + RTX 5090, 168,000 根合成 1m bar)

| 项 | 耗时 | 吞吐 |
|---|---|---|
| 参考引擎 (纯 Python) | 4,628 ms | 0.04 M bar/s |
| 内核首次 (含 JIT 编译) | 631 ms | — |
| 内核热运行 | **9.0 ms** | 18.6 M bar/s (**提速 513x**) |
| CPU 扫描 1000 组 (8 线程) | 1.45 s | 0.13 G bar-steps/s |
| GPU 扫描 1000 组 (单 launch) | 1.17 s | 0.14 G bar-steps/s (线程少未吃饱) |
| GPU 扫描 10000 组 | **1.30 s** | **1.25 G bar-steps/s** (≈ CPU 同规模 10x) |

参考引擎与内核在同一数据上的成交数/资金/持仓完全一致 (脚本内断言);
**GPU 与 CPU 内核 1000 组逐位核对 0 组不一致** (float64 + --fmad=false + 同式浮点表达式)。
真实数据冒烟: 159992.SZ 3.6 万根 + 9 组 walk-forward 扫描 2.28s (含首次编译)。

## 6. GPU 档 (已实现, gpu.py)

> 2026-09-06 步骤 1~2 起另有**通用 CUDA kernel** (`cuda_sweep_window_generic`):
> 策略段是 DSL 渲染的 `__device__ int strategy_check(...)` (编译期注入),
> 参数走 `params_arr` (按 params_spec 顺序, 上限 8 个); sweep 对带 DSL 的
> 策略 device=gpu 自动走它, 全指标与 CPU DSL 内核逐位一致 (见 14 号文档)。
>
> **2026-09-08 迁移** (commit `dfd4785`): DSL→CUDA 投影函数 (`render_cuda_device_function` /
> `build_cuda_state_decls` / `build_cuda_strategy_check_call` / `build_cuda_device_header`)
> 已从 `core/gpu.py` 迁至 `strategies/dsl.py` (gpu.py:58-62 注明; gpu.py:296-301 导入)。
> `core/gpu.py` 只保留 CUDA kernel 源码模板 + 编译 + 调度基础设施, **不再持有策略投影逻辑**。
>
> 通用模板 `_CUDA_SOURCE_GENERIC_TEMPLATE` (gpu.py:75-268) 有三个编译期占位符 (gpu.py:320-323 替换):
> `{STRATEGY_BODY}` (策略 device 函数体) + `{STATE_DECLS}` (state_spec 字段寄存器声明,
> dsl.py:542-568) + `{STRATEGY_STATE_ARGS}` (strategy_check 调用处的 state arg 列表,
> dsl.py:571-581); 后两者按策略 `state_spec` 注入。

- **栈**: RTX 5090 (sm_120/Blackwell) + 驱动 CUDA 13.1, 无本地 toolkit。
  依赖来自 pip: `cupy-cuda12x` + `nvidia-cuda-runtime/nvrtc/cublas/cufft/curand/
  cusolver/cusparse-cu12` (gpu.py `_ensure_cupy` 自动把轮子里的 DLL 目录挂进进程 PATH)。
  NVRTC 按设备架构编译 PTX (失败回退 compute_90), 由驱动 JIT 到 sm_120。
- **设计**: 一线程 = 一组参数, 顺序扫 bar (流式语义); **桶 ts/mark 与参数无关,
  按周期分组预计算一次共享** (numpy 向量化整数历法), 内核循环零 int64 除法
  (GPU 上 64 位除法是软件模拟); 状态全寄存器, 不落逐笔成交;
  `--fmad=false` + 与 CPU 同式浮点表达式 => 逐位一致。
- **何时用 GPU**: 网格 ≳ 数千组后 GPU 占用率吃满, 收益明显 (1 万组以上 ~10x 于 8 线程 CPU);
  小网格 CPU 更省事 (无传输/编译开销)。消费级卡 FP64 吞吐是硬上限, 更大加速需数据中心卡。
- **差分**: tests/test_gpu.py —— GPU vs CPU 64 组参数 (跨周期/tf1) 逐位一致 + 走窗隔离 + 吞吐冒烟。
