## 2. 性能内核: CPU 向量化 vs GPU 向量化 (2026-09-09 重写)

### 2.1 核心思想: 双端统一向量化

不再有"流式内核 + DSL 三端转译"。唯一执行入口是 `run_vectorized(bars_1m, period, warmup_until, strategy, params, device, ...)`:

| 场景 | 用法 | 特点 |
|---|---|---|
| 回测 (CPU) | `run_vectorized(..., device="cpu")` | numpy 算子; `xp.where / cumsum / ...` 全部 numpy 调用 |
| 回测 (GPU) | `run_vectorized(..., device="gpu")` | cupy 算子; 同样 API 透明换 backend |
| 扫描 | 每组参数一个 `run_vectorized`; ThreadPoolExecutor 并行 | numpy 路径 nogil; cupy 路径需单线程 (GPU 占用) |
| 实盘 | `Engine.on_bars` 逐 bar 调 `compute_signals_for_one_bar(xp, bar, params)` | 同 compute_signals 共享 FSM 函数 |

### 2.2 实现要点

- **桶聚合** = `_aggregate_buckets_xp(xp, bars_1m, period_seconds, warmup_until)`:
  用 `xp.diff / xp.cumsum / searchsorted` 把 1m bar 数组聚合为桶级 OHLCV 数组。
  桶 ts / mark 用 `timeutils.bucket_ts_encoded` 整数化历法 (避免 GPU 上 int64 除法)。
- **桶级数组契约**: `{"ts", "o", "h", "l", "c", "v", "mark", "n_bars"}` — 全 1D 数组。
- **浮点路径**: CuPy 高阶封装的 GPU 算子舍入与 CPU 不同, **不保证 bitwise**;
  但策略逻辑确定性 + 同输入, 结果在 ULP 级容差内 (`test_ma_crossover_cpu_vs_gpu` 锁定)。
- **桶 CLOSE 语义**: 向量化路径在"桶级 finalized OHLCV"上算指标;
  `Engine.on_bars` 在桶**切换**那一刻用上一桶 finalized OHLCV 驱动策略 (与 vectorized 同口径)。
  `reconcile` 测试通过 `bucket_diff_cap=8` 容忍 EMA 累积顺序漂移。
- **指标未就绪**: `xp_ema_channel` 返回 `xp.nan` 占位; 策略代码 `xp.where(xp.isnan(up), 0.0, up)` 转 0 守卫;
  与 Engine 路径的 `if up == 0.0 or dw == 0.0: return 0` 等价。

### 2.3 持久状态

| 路径 | 状态存放 |
|---|---|
| vectorized (`compute_signals`) | 函数内局部 (FSM), 跨桶不持久 |
| Engine (`compute_signals_for_one_bar`) | instance 属性 (`self._up_st / _dw_st / _fsm`), 跨桶持久 |

channel_deviation 同时覆写 `compute_signals_for_one_bar` (instance 路径) 与 `compute_signals` (局部 FSM 路径);
**两种入口通过共享 `_fsm_step(state, ...)` 保证信号 bitwise 一致**。

### 2.4 metrics 16 字段 (2026-09-09 补齐)

`vectorized_engine._execute_trades` 累积 `equity_curve / baseline_curve` (O(n));
末尾调 `metrics.summarize(equity_curve, baseline_curve, ..., years, n_trades, n_buy, n_sell, turnover, ...)`:

| 字段 | 含义 |
|---|---|
| `final_cash / final_position / final_equity` | 终态 |
| `n_trades / n_buy / n_sell / turnover` | 成交统计 |
| `cagr` | 年化超额 (final/baseline 比值年化) |
| `sharpe / sharpe_excess` | 日频收益 + 超额曲线的夏普 |
| `sortino / sortino_excess` | 下半方差 Sharpe |
| `calmar` | cagr / max_drawdown |
| `max_dd_days` | 最大回撤持续天数 |
| `max_dd_recovered` | 最大回撤恢复天数 |
| `max_drawdown` | 最大回撤幅度 |

## 3. 等价性保证 (差分 / 对账测试)

`tests/test_strategy_unified.py` + `tests/test_replay_v2.py` + `tests/test_vectorized.py`:

1. **CPU vs GPU 容差**: 同一策略同参数, `np.array_equal(sig_cpu, sig_gpu)`, summary 浮点字段 1e-6 容差 (`test_ma_crossover_cpu_vs_gpu`)。
2. **vectorized vs Engine 桶级对账**: `reconcile(...)` 比逐桶 sig + 逐笔成交 (ts/side/qty/price), 默认 `bucket_diff_cap=8`, strict 模式 cap=0。
3. **MA 交叉语义**: numpy 独立算 EMA + 交叉, 与 vectorized 引擎输出对比 (`test_vectorized_ma_crossover_logic`)。
4. **ma_crossover vs channel_deviation**: 两个策略在 CPU/GPU/vectorized/Engine 四条路径上的 6 项核心断言 (signature / dtype / cpu-vs-gpu / vectorized-vs-Engine / metrics 字段集)。

## 4. 并发扫描 (sweep.py + cli)

```bash
# 真实数据 (MySQL 自动拉取并缓存 npz, 二次运行零数据库开销)
python -m evtrade sweep --strategy channel_deviation --code 159992.SZ \
    --start 20250101 --end 20260903 --device auto \
    --data-cache cache \
    --grid "low1=1.0,1.5,2.0" --grid "high2=0.3,0.5,0.8" \
    --split 20250701 --workers 16 --out results.csv

# 无库体验 (合成数据)
python -m evtrade sweep --strategy channel_deviation --synthetic-days 120 \
    --start 20250601 --end 20250701 --device cpu \
    --grid "low1=0.4,0.6,0.8"

# GPU 档 (需 cupy + nvidia-*-cu12 pip 轮子)
python -m evtrade sweep --strategy channel_deviation ... --device gpu
```

- 每组参数 = 一次 `run_vectorized`, ThreadPoolExecutor 并行。
- `--device cpu` 多线程吃满 (numpy nogil); `--device gpu` 单线程 (GPU 占用)。
- `--split YYYYMMDD` 输出 train_*/test_ 两套指标; 按 score 排序 (见 13 文档)。
- 网格键: low1/low2/high1/high2/period/trade_qty/scale (策略私有参数如 `tf1` 在 `params_spec` 声明后透传扫描)。

## 5. 性能特性 (2026-09-09 重构后)

旧版 numba 加速特性 (`tests/test_kernel_unit.py::test_live_step_equals_batch` 期望微秒级 step) 已作废——本版无 JIT 内核。
**速度特性**:
- numpy 路径: 批量向量化吞吐 ≈ 0.05~0.2 M bar/s (取决于策略复杂度, channel_deviation 含 FSM Python 循环较慢);
- cupy 路径: 算子自身吞吐接近 numpy (cupy 高阶封装无显著加速); 主要优势在大网格并发 (单 GPU batch);
- 实盘路径 (`Engine.on_bars`): 逐 bar Python 调用 + instance 维护, 吞吐 ≈ 1~5 K bar/s, 满足实盘 1m bar 节奏。

> 旧基准 (168K bar / 9 ms) 已不适用。新基准待 `scripts/benchmark.py` 改写后提供。

## 6. GPU 档 (2026-09-09 简化)

> **2026-09-09 简化**: 删除 `core/gpu.py::cuda_sweep_window_generic` (NVRTC 编译 + 通用 CUDA kernel);
> 删 `strategies/dsl.py` (含所有 CUDA 投影函数); 删 `core/gpu.py` 中所有 `CUDA_DEVICE_*` 字符串常量。
>
> GPU 路径现只通过 cupy 算子 (`xp.where / cumsum / searchsorted / ...`) 自动获得, 无需手写 CUDA C99。

- **栈**: 消费级 NVIDIA GPU + `cupy-cuda12x` + `nvidia-*-cu12` pip 轮子。
- **设计**: cupy 高阶算子 (cumprod / cumsum / searchsorted) 内部走 cuBLAS / cuDNN 预编译 kernel。
  桶 ts/mark 用整数化历法预计算 (numpy 向量化), 避免 GPU 上 int64 除法。
- **何时用 GPU**: 与 CPU 路径吞吐差距不大; 主要价值在大网格并发 (单 GPU 一次处理数千组参数)。
- **失败回退**: cupy 不可用时 `--device auto` 自动 fallback cpu 并打 warning。
