## 2. 策略参数通用 dict 模式(2026-09-06)

### 2.1 三种调用形式(等价)

策略参数**不再依赖固定关键字名**,统一以 `dict[str, Any]` 传递:

```python
from evtrade.strategies import get_strategy

# 形式 1: dict 传入 (推荐, 适合 grid 扫描)
s = get_strategy("channel_deviation", params={
    "low1": 1.5, "low2": 1.0, "high1": 1.5, "high2": 0.5,
})

# 形式 2: kwargs 传入 (兼容旧 API, 适合单次回测)
s = get_strategy("channel_deviation", low1=1.5, low2=1.0)

# 形式 3: 混合 (dict 优先, kwargs 填默认)
s = get_strategy("channel_deviation", params={"low1": 2.0}, low2=1.5)
```

### 2.2 策略声明参数 schema (`params_spec`)

每个策略类声明 `params_spec`,基类自动**校验类型 + 默认值 + 范围**:

```python
from evtrade.strategies import StrategyBase, register_strategy

@register_strategy("my_strategy")
class MyStrategy(StrategyBase):
    params_spec = {
        "lookback":      {"default": 20,    "type": int,   "min": 2,    "max": 1000},
        "threshold_pct": {"default": 0.001, "type": float, "min": 0.0,  "max": 0.1},
    }
    def __init__(self, params=None, **kwargs):
        super().__init__(params=params, **kwargs)  # 自动填默认 + 校验
        # self.lookback / self.threshold_pct 已可用
    def check(self, cur, indicators):
        if cur["close"] > self.threshold_pct * 100:
            return "BUY", {...}
```

校验失败时报 `ValueError`(未声明 key) / `TypeError`(类型错) / `ValueError`(超范围)。

### 2.3 CLI 单次回测 (--params)

```bash
# 完整形式
python -m evtrade backtest --strategy channel_deviation ^
    --params "low1:1.5;low2:1.0;high1:1.5;high2:0.5" ^
    --period 5m --start 20250101 --end 20260903 --data-cache cache

# 缺省 (用 --params 全部覆盖; 不传则走通道偏离策略默认)
python -m evtrade backtest --strategy channel_deviation ^
    --params "low1:2.0;low2:1.2" ^

# 带 DSL 的策略 (如 dev_trigger): kernel 引擎直接可用 (DSL 特化内核)
python -m evtrade backtest --strategy dev_trigger ^
    --params "entry_dev:0.5" ^
    --period 5m --start 20250101 --end 20260903 --data-cache cache

# 无 DSL 的策略 (如 breakout): 走 --engine ref (参考引擎, 比 kernel 慢 ~500x)
python -m evtrade backtest --strategy breakout ^
    --params "lookback:30;breakout_pct:0.002" ^
    --engine ref --period 5m ...

# ℹ️ kernel 引擎支持 channel_deviation (冻结内核) + 一切带 DSL docstring 的
# 策略 (DSL 特化内核, 见 14 号文档); 无 DSL 的策略请用 --engine ref
```

`--params` 解析规则:
- 形式: `k1:v1;k2:v2`(分号分隔 kv 对)
- 类型推导: `42`→int, `3.14`→float, `true`/`false`→bool, 其他→str

### 2.4 CLI 网格扫描 (--grid)

```bash
# channel_deviation (走 kernel/sweep, 高速)
python -m evtrade sweep --strategy channel_deviation ^
    --grid "low1=1.0,1.5,2.0" --grid "high2=0.3,0.5,0.8" ^
    --data-cache cache --workers 8 --out results.csv

# 带 DSL 的策略 (如 dev_trigger): 走 DSL 特化 numba 内核 (高速);
# device=gpu 时走通用 CUDA kernel (与 CPU 逐位一致)
python -m evtrade sweep --strategy dev_trigger ^
    --grid "entry_dev=0.5,0.8" ^
    --workers 4 --out dev_trigger_results.csv

# 无 DSL 的策略 (如 breakout): 走 run_one_general + 参考引擎, 慢 ~500x
python -m evtrade sweep --strategy breakout ^
    --params "lookback:20;breakout_pct:0.001" ^
    --grid "lookback=10,20,30" --grid "breakout_pct=0.0005,0.001,0.002" ^
    --workers 4 --out breakout_results.csv
# ^ grid key 白名单 = GRID_KEYS + 该策略 params_spec (自动放行)
```

**关键点**:`--grid key=v1,v2,v3` 笛卡尔积;grid key 必须出现在
`--params` 的 key 集合或 `GRID_KEYS` 公共白名单中。

### 2.4.1 `--params` 与 `--grid` 的语义(2026-09-06 修正)

| 关系 | 行为 | 示例 |
|---|---|---|
| `--params "k:基础值"` + `--grid "k=v1,v2"` | `--grid` 覆盖基础值,沿用的参数取基础 | `--params "lookback:20;breakout_pct:0.001"` + `--grid "lookback=10,30"` → 扫 2 行,`breakout_pct=0.001` 不变 |
| 不传 `--params` + `--grid "k1=v1,v2;k2=v3,v4"` | 完全笛卡尔积 | `--grid "lookback=10,20,30;breakout_pct=0.0005,0.001"` → 6 行 |
| `--params "k1:v1"` + `--grid "k2=v2"` | `--params` 提供 k1,`--grid` 提供 k2 → 1 行(无 grid 笛卡尔) | `--params "lookback:20"` + `--grid "breakout_pct=0.0005,0.001"` → 2 行(breakout_pct 笛卡尔,lookback 沿用 20) |

**核心规则**:`--params` 提供**基础值/默认值**;`--grid` 在指定 key 上**扫描**,未在 grid 的 key 沿用 `--params` 的基础值。

### 2.6 已知边界

| 项 | 说明 |
|---|---|
| kernel 引擎 | 只支持 `channel_deviation` (low1/low2/high1/high2 写死在 jitclass);其他策略必须用 `--engine ref` 或 `strategy_name=非channel` 的 sweep |
| Sharpe/Sortino/Calmar/CAGR | `run_one_general` (非 channel_deviation) 暂不计算(只输出 excess/turnover 等基础指标);若需全指标,用参考引擎 `_run_ref` 单独跑 |
| GPU 扫描 | 同样只支持 channel_deviation 固定参数;新策略无法用 GPU |
| grid key 校验 | 必须出现在策略 `params_spec` 或 `GRID_KEYS` 白名单 |

### 2.7.1 目录约定

所有策略放在 `evtrade/strategies/` 子包,**一个策略一个文件**:

```
evtrade/strategies/
```

### 2.7.2 模板骨架(直接复制)

```python
from __future__ import annotations
"""<策略名>: <一句话功能描述>

================================================================
✅  可改层 (strategies 子包)  ✅
================================================================
<详细说明: 适用场景 / 锁存逻辑 / 状态机 / 引用文档>
================================================================
"""
from .base import StrategyBase, register_strategy


@register_strategy("my_strategy")              # ← 唯一标识, CLI --strategy 用
class MyStrategy(StrategyBase):
    """<docstring, 给 jupyter 看>"""

    # ============ 参数 schema (必填) ============
    params_spec = {
        # key:        {"default": ..., "type": int/float/bool, "min": ..., "max": ...}
        "lookback":     {"default": 20,    "type": int,   "min": 2,    "max": 1000},
        "threshold":    {"default": 0.001, "type": float, "min": 0.0,  "max": 0.1},

    # ============ 构造 (必填, 按模板) ============
    def __init__(self, params: dict | None = None, **kwargs):
        super().__init__(params=params, **kwargs)   # ← 必须第一行, 自动填默认+校验

        self._acted = False

        self._lows: list[float] = []

    # ============ 核心: check (必填) ============
    def check(self, cur: dict, indicators: dict) -> tuple[str | None, dict]:

        cur 字段 (来自 evtrade.frozen.models.Bar + 桶合并):

        up = indicators.get("up")
        dw = indicators.get("dw")
        # === 1) 指标未就绪: 直接 return ===
        if up is None or dw is None:
            return None, {}

        # === 2) 桶切换: 重置单桶单操作锁 (推荐) ===
        if cur["ts"] != self._bucket_ts:
            self._bucket_ts = cur["ts"]
            self._acted = False

        # === 3) 状态维护 / 计算偏离量 ===
        # ... 你的策略逻辑 ...

        # === 4) 触发信号 ===
        if <条件>:
            self._acted = True
            return "BUY", {"<info_key>": <value>, ...}

        if <另一条件>:
            self._acted = True
            return "SELL", {"<info_key>": <value>, ...}

        return None, {"<info_key>": <value>, ...}
```

### 2.7.3 完整示例:区间突破策略

`strategies/example_breakout.py` 是真实可跑的示例:

```python
from __future__ import annotations
"""示例策略: 区间突破 (示意用, 仅参考引擎)"""
from .base import StrategyBase, register_strategy


@register_strategy("breakout")
class BreakoutStrategy(StrategyBase):
    """N 根 1m bar 区间突破"""

    params_spec = {
        "lookback":     {"default": 20,    "type": int,   "min": 2,    "max": 1000},
        "breakout_pct": {"default": 0.001, "type": float, "min": 0.0,  "max": 0.1},
    }

    def __init__(self, params: dict | None = None, **kwargs):
        super().__init__(params=params, **kwargs)
        self._bucket_ts = None
        self._acted = False
        self._highs: list[float] = []
        self._lows: list[float] = []

    def _push(self, h: float, l: float):
        self._highs.append(h)
        self._lows.append(l)
        if len(self._highs) > self.lookback:
            self._highs.pop(0)
            self._lows.pop(0)

    def check(self, cur, indicators, dw=None):
        # 兼容 (cur, up, dw) 与 (cur, dict) 两种调用
        if isinstance(indicators, dict):
            pass
        if cur["ts"] != self._bucket_ts:
            self._bucket_ts = cur["ts"]
            self._acted = False
        self._push(cur["high"], cur["low"])
        if len(self._highs) < self.lookback or self._acted:
            return None, {}
        hi, lo = max(self._highs), min(self._lows)
        c = cur["close"]
        info = {"hi": hi, "lo": lo, "close": c}
        if c > hi * (1 + self.breakout_pct):
            self._acted = True
            return "BUY", info
        if c < lo * (1 - self.breakout_pct):
            self._acted = True
            return "SELL", info
        return None, info
```

### 2.7.4 验证清单(逐项必过)

新建一个策略后,按这个清单走一遍(任何一项不达标都不能发布):

- [ ] **1. 注册可见** — `from evtrade.strategies import available_strategies; print(available_strategies())` 含你的 key
- [ ] **2. 三种形式** — `get_strategy("key")` / `get_strategy("key", params={...})` / `get_strategy("key", k=v)` 都能构造
- [ ] **3. 默认值** — `get_strategy("key").params` 含所有声明的 key (默认值填好)
- [ ] **4. 类型校验** — `get_strategy("key", params={"k": "wrong_type"})` 抛 `TypeError`
- [ ] **5. 范围校验** — 超出 `min/max` 抛 `ValueError`
- [ ] **6. 未声明 key** — `get_strategy("key", params={"bogus": 1})` 抛 `ValueError`
- [ ] **7. 跑一次合成数据** — 不报错,信号行格式正确,信号数 > 0 (或明确无信号时返回 None)
- [ ] **8. 回放对账** — `--engine ref` 跑一次,有成交(可选)

| 项 | 说明 |
|---|---|
| **走参考引擎** | 新策略默认走参考引擎(慢 ~500x);要快,只能改 numba kernel(冻结层, 改 = 重测 56 项差分) |

### 2.7.7 进阶:状态保存(实盘场景)

实盘时**进程重启**会丢内存中的策略状态。**两种选择**:

- [ ] **简单**(推荐起步): 重启后从 warmup_until 开始累积,丢历史信号 — 可接受
- [ ] **完整**: 增加 `get_state() -> dict` / `set_state(state: dict)` 方法把 `self._bucket_ts / _highs / _lows / ...` 持久化到磁盘

`StrategyBase` 已预留这两个方法名(默认 no-op),子类覆盖即可。

### 2.7.8 完整工作流:从一个想法到参数化


### 3.1 策略与执行端

| 参数 | 默认 | 适用 | 说明与用法 |
|---|---|---|---|
| `--strategy` | `channel_deviation` | backtest/sweep | 策略 key(`evtrade.strategies.available_strategies()`)。内置:`channel_deviation` 通道偏离回撤(冻结内核,最快);`dev_trigger` 轨道触发(**带 DSL,三端同源示例**);`breakout` 区间突破(**无 DSL,仅参考引擎**);`template_demo` 测试模板 |

| 参数 | 默认 | 适用 | 说明与用法 |
|---|---|---|---|
| `--tf1` | `21` | 三者 | 通道轨 EMA 周期:`UP = EMA(H, tf1)`、`DW = EMA(L, tf1)`(通达信蓝色通道轨) |
| `--low1` | `1.5` | 三者 | 下轨**极端偏离**阈值(%):`L` 低于下轨该幅度 → 置位 BUY 预备。仅 channel_deviation 口径;backtest/sweep 里被 `--params "low1:..."` 覆盖(未传 `--params` 时才生效);replay 无 `--params`,始终生效 |
| `--low2` | `1.0` | 三者 | 下轨**回撤确认**阈值(%):`H` 相对下轨回撤到该位置 → 触发 BUY。**必须 < low1**(迟滞) |
| `--high1` | `1.5` | 三者 | 上轨**极端偏离**阈值(%):`H` 高于上轨该幅度 → 置位 SELL 预备 |

| `--trade-qty` | `10000` | backtest/sweep | 每次信号交易股数(倍投的基础数量) |

| `--all-in` | 关 | 三者 | 全仓模式:BUY 吃满现金 / SELL 清光持仓;等价 `--buy-pct 1.0 --sell-pct 1.0` |

## 4. 批量网格回测 + 找最优参数:标准流程

### 4.1 三层选参原则(对照 `kbs/13`)

**硬过滤**(`filter_pass` 列,任一不满足即出局)
- 各 test 窗成交笔数 ≥ `--min-trades`(默认 30)——笔数太少无统计意义
- 各 test 窗权益回撤 ≤ `--max-mdd`(默认 1.0=不限;实盘建议 0.15)

**主排序指标 `score`**
```
score = ann_net_min / (1 + λ · S)
ann_net_min = min(各 test 窗的年化扣费超额)
S            = 邻域衰减 (邻居平均 ann_net_min 相对自身的相对衰减, 截断到 [0,1])
```
- **取最差窗而非均值**:单窗冠军大概率是运气;在最不利验证段也不亏的参数才能上实盘
- **λ (`--score-lambda`)**:越大越偏"参数平原中心",规避孤立尖峰
- **费率 (`--fee-bp`)**:直接进主指标,堵住高频参数的幻觉

**显著性 (`--mc N`)**:`score` 前 `--mc-top` 名 → 自然日整块打乱行情 N 次 → p 值
- p 小只说明"显著好于无结构运气",**必要而非充分**
- **绝对收益为负时仍不可用**

**口径**
- `策略总资产 = cash + position × last_price`
- `baseline = init_cash + init_position × last_price`(什么都不做的终值)
- `盈亏差额 = 策略总资产 − baseline` = 择时贡献(消除标的本身涨跌)
- `最大回撤 = 权益曲线逐 bar 盯市最大回撤`(只作硬约束,不参与排序)
- `成交额合计` = 买入成交价 × 数量 + 卖出成交价 × 数量(双计)
- `内核耗时` = 策略期 run_backtest 耗时(含 JIT 编译;二次运行仅热运行 ms 级)

**信号行字段**(`info` dict 快照,详见 `kbs/03` §5)
- `low_dev = (DW - L)/DW*100` → 下轨极端偏离度
- `high_dev = (H - UP)/UP*100` → 上轨极端偏离度
- `low_dev_h = (DW - H)/DW*100` → H 相对下轨的回撤(BUY 触发)
- `high_dev_l = (L - UP)/UP*100` → L 相对上轨的回撤(SELL 触发)
- `low_hit_prev / high_hit_prev` → 进入本根前的锁存标记(`True`=置位)

`----` 表示数值是 `None`/`NaN`(指标未就绪);注意 bool 是 int 的子类,`low_hit_prev=False` 会被 `fmt` 显示为 `0.0000`。

### 5.2 sweep 输出(CSV 列全表)

| 列名族 | 含义 |
|---|---|
| `low1` / `low2` / `high1` / `high2` / `tf1` / `period` / `trade_qty` / `scale` | 网格参数本身(笛卡尔积) |
| `train_*` / `test*_*` | 单窗原始指标(各窗一份);`train`=起算到第 1 个 split;`test1`/`test2`/...=各滚动窗 |
| `full_*` | 单窗模式(无 WFO)下的指标 |
| `ann_net` / `train_ann_net` / `test*_ann_net` | 各窗**年化扣费超额%**: `excess_pct/years − turnover × fee / baseline / years × 100` |
| `ann_net_min` | 所有 test 窗 `ann_net` 的最小值 → **主判据** |
| `ann_net_mean` | 所有 test 窗 `ann_net` 的算术平均 |
| `pos_ratio` | `ann_net > 0` 的 test 窗占比(0~1) |
| `sharpe_min` | 所有 test 窗 `sharpe_excess` 的最小值 |
| `x_mdd_max` | 所有 test 窗超额曲线最大回撤的最大值(择时懊悔深度) |
| `S` | 邻域衰减 ∈ [0,1](邻居平均 `ann_net_min` 相对自身的相对衰减);孤立尖峰 → 接近 1,平原中心 → 0 |
| `score` | `ann_net_min / (1 + λ · S)`(`ann_net_min<=0` 原样透传);**主排序指标** |
| `pareto` | 双目标 `(ann_net_mean, sharpe_min)` 非支配标记 |
| `filter_pass` | `min_trades` + `max_mdd` 硬过滤是否通过 |
| `n_trades` / `final_equity` / `baseline` / `excess` / `excess_pct` / `years` / `ann_excess_pct` / `sharpe_excess` / `x_mdd` / `max_drawdown` / `turnover` | 内核 `summarize()` 直出(无前缀=对应"full"或末尾窗) |

**怎么看**
1. 先看 `filter_pass=True` 的(过不了硬过滤直接出局)
2. 按 `score` 降序取前 3~5 名
3. 看 `ann_net_min`(是否所有 test 窗都正收益)、`pos_ratio`(几窗正)、`sharpe_min`(最差窗择时平稳性)、`S`(是否孤立尖峰)
4. 若启用了 MC,看 `p_value`(`--mc-top` 名后的终端输出)
5. 选**头部位 + S 小 + pos_ratio=1.0 + MC p 小 + ann_net_min 为正**的一组

## 7. 资金模式参数化(2026-09-05 阶段 2)

### 7.1 三种模式的语义与何时用

| 模式 | 命令 | 语义 | 适用场景 |
|---|---|---|---|
| **fixed-qty(默认)** | 不传 / `0/0/0` | 每次 `min(trade_qty, 资金/持仓上限)`,倍投时 `上次 × scale` | 与历史行为一致;底仓 20 万股 + 单笔 1 万股做加减仓 |
| **all-in** | `--all-in` | BUY 吃满现金 / SELL 清光持仓 | 信号稀疏(每天 0~2 个)、想用满仓吃反弹 |
| **比例模式** | `--buy-pct 0.5 --sell-pct 1.0` | BUY 按 `buy_pct × 现金 / 价格` 买,SELL 按 `sell_pct × 持仓` 卖 | 多标的组合的固定权重;单标的的"轻仓试探 + 重仓确认" |

### 7.2 优先级规则

```
1. 显式 --buy-pct / --sell-pct 始终生效 (>= --all-in)
2. --all-in 把 buy_pct/sell_pct 提升为 1.0, 但被显式参数覆盖
3. 比例模式 + 倍投可同时开启: 倍投 cur_qty 仍作"上限保护"
   (但比例模式下不会触发截断, 因为比例本身就按当下资金算)
```

### 7.3 典型命令

```bash
# 全仓进出 (单标的均值回归 + 信号稀疏)
python -m evtrade backtest --period 5m --start 20250101 --end 20260903 ^
    --data-cache cache --all-in

# 半仓买 + 全仓卖 (试探 + 兑现)
python -m evtrade backtest --period 5m --start 20250101 --end 20260903 ^
    --data-cache cache --buy-pct 0.5 --sell-pct 1.0

# 30% 仓 + 清仓 (组合里固定权重)
python -m evtrade backtest --period 5m --start 20250101 --end 20260903 ^
    --data-cache cache --buy-pct 0.3 --sell-pct 1.0

# 比例 + 倍投 (激进试探)
python -m evtrade backtest --period 5m --start 20250101 --end 20260903 ^
    --data-cache cache --buy-pct 0.5 --sell-pct 1.0 --scale 1.5

# 网格扫描里也作为维度
python -m evtrade sweep --code 159992.SZ --start 20250101 --end 20260903 ^
    --data-cache cache --warmup-days 365 ^
    --grid "low1=1.0,1.5,2.0" --grid "all_in=true,false" ^
    --splits 20260101,20260401 --workers 8 --out results_funding.csv
```

### 7.4 实测对比(synthetic 240 天, low1=1.5, tf1=21)

| 模式 | n_trades | ann_excess_pct | Sharpe | Sortino | Calmar | max_dd | max_dd_days |
|---|---|---|---|---|---|---|---|
| fixed-qty | 936 | +56.67%/年 | 2.16 | 2.17 | 1.40 | 40.6% | 0 |
| all-in | 370 | +14.46%/年 | 0.25 | 0.22 | 0.32 | 45.1% | 0 |
| buy_pct=0.3 / sell_pct=1.0 | 785 | +13.03%/年 | 0.18 | 0.16 | 0.42 | 30.7% | 0 |

**结论**:
- **合成数据下 fixed-qty 最优**(信号足够多,1 万股交易吃满收益)
- **all-in 在合成数据上 Sharpe 低、回撤高**(单笔全押波动大)
- **真实数据上需要重测** —— 信号稀疏时 all-in 反而好;信号密集时固定股数更稳
- **永远跑网格**:把 `all_in` 当成与 `low1/low2` 同级的维度扫一遍

### 7.5 与 baseline 口径的相互作用

| `init_position` | `init_cash` | 资金模式 | baseline = ? | 含义 |
|---|---|---|---|---|
| 20 万股 | 20 万 | 任意 | `20万 + 20万×期末价` | "底仓不动"基线 |
| 0 | 20 万 | all-in | `20万 + 0 = 20万` | "纯现金"基线;`ann_excess_pct` ≈ 超越现金的择时 |
| 0 | 20 万 | buy_pct=0.5 | 同上 | 同上 |

> 把 `init_position=0` 配 `--all-in`,就是"纯择时 + 现金管理"的回测;`baseline` 从"底仓 + 现金"退化成"现金",`ann_excess_pct` 物理意义从"择时贡献"变成"超越现金的收益"。这是更纯粹的 α 衡量,**对均值回归策略更干净**。

## 8. 常见问题(FAQ)

**Q: 完全没有信号?**
1. 确认预热充分(`--period 1d` 且 start 前历史不足一年会导致指标就绪晚)
2. 把 `--low1` 临时调小(如 0.5)看是否开始出信号,判断阈值过严 vs 数据问题
3. 看 `--show-bars` 或 `--bars-out` 输出中 `low_dev`/`high_dev` 的实际分布

**Q: 信号时间戳为什么是 10:15 而我以为是 10:10~10:14 的行情?**
桶 ts 是前开后闭区间的右端点。`[10:15]` 桶覆盖 `(10:10, 10:15]`。详见 `kbs/04`。

**Q: 能多标的吗?**
单次单标的。循环 `--code` 或自行扩展 Feed(见 `kbs/11`)。

**Q: 倍投为什么账户突然全仓买入了?**
资金/持仓上限保护下,3~4 次连续倍投就会触顶。看 `position × last_price` 与 `cash` 的关系 —— 倍投在该标的上可能放大回撤与费用,**必须进网格验证**(见 `kbs/06` §8)。

**Q: Ctrl+C 会丢汇总吗?**
不会。`run()` 捕获后仍执行 `flush()` 与 `print_summary()`,基于已处理数据出汇总(未拉取的后续段自然缺失)。

**Q: 数据库密码怎么办?**
用环境变量 `EVTRADE_DB_URL` 覆盖默认值;不要把含凭据的文件提交到公开仓库。

**Q: `--mc` 该设多少?**
默认 200~300 适合自测;发论文级结论建议 1000+;`--mc-top` 越大越耗时,与 `N` 乘积正比于 MC 总耗时。

**Q: 网格怎么起步?**
- 先**单维粗扫**(`--grid "low1=0.5,1.0,1.5,2.0,3.0"` 等)看哪些维度真的有影响
- 再**两两组合**(`--grid low1=... --grid low2=...`)
- 最后**WFO 多窗 + MC** 验证最稳的一组
- 网格大小经验上限:CPU 端 8 线程 ~数分钟跑 1000 组;GPU 端 1 万组数秒;再大需考虑分批
