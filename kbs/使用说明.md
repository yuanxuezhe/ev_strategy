## 0. 安装与前置

### 0.1 依赖

核心依赖 5 个：`numpy / pandas / sqlalchemy / pymysql / torch`（无 numba）。
**GPU 没有独立安装路径**：`torch` 是核心依赖，CPU 与 CUDA 是同一个 torch 包的两个 wheel
（由平台/安装源决定，不能并存；换运行时需要重装 torch）：

```bash
# CPU（默认，任何机器）
pip install -e .
# 或装 CUDA 版 torch（NVIDIA + CUDA runtime，示例 CUDA 12.4）
pip install torch --index-url https://download.pytorch.org/whl/cu124
```

### 0.2 uv 安装（推荐）

按 [astral-sh/uv](https://github.com/astral-sh/uv) 安装：

```bash
# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```bash
# 仓库根目录
uv sync                  # 建 .venv + 装全部依赖 + 编辑模式装本项目
uv sync --group dev      # 含开发工具 (pytest 等)
uv run python -m evtrade ...   # 跑命令
uv run pytest            # 跑测试（GPU 测试默认 skip；--gpu 显式开启）
uv run evtrade ...       # 等价简写 (pyproject [project.scripts] 注册的入口)
```

`uv sync` 自动：选最新兼容 Python（>= 3.8）、建 `.venv`、解析 lockfile（`uv.lock`，
默认不入仓库，见 0.5）、编辑模式装本项目。

### 0.3 故障排查

- **`uv sync` 报 requires-python 不满足**（`Package 'foo' requires a different Python`）：
  显式指定 Python —— `uv python install 3.11` + `uv sync --python 3.11`。
- **torch 报 `Torch not compiled with CUDA enabled`**：装的是 CPU wheel。
  换 CUDA 版：`pip install torch --index-url https://download.pytorch.org/whl/cu124`。
  装对后 `--device auto` 自动路由 CUDA；`--device gpu` 在 CUDA 不可用时**抛错**（提示改用
  `auto`/`cpu`），`--device auto` 才降级 cpu + warning。
- **`uv lock` 不一致（团队协作）**：`uv lock --check` 验证 / `uv lock` 重新生成。
- **离线 / 公司内网**：`uv sync --offline`（本地缓存）；`uv export > requirements.txt`
  （导出供 pip 离线装）。

### 0.4 非 uv 流程

无 uv 也可：`python -m venv .venv` → 激活 → `pip install -e .` → `python -m evtrade ...`。
`pyproject.toml` 是单一事实源，pip + setuptools 同样可用。

### 0.5 uv.lock 与团队协作

`uv.lock` 默认**不入仓库**（`.gitignore` 已排除）：每位开发者本地 `uv lock` 生成自己的
lockfile；CI / 实盘机可直接 `uv sync`（从 `pyproject.toml` 解析）。如需锁定全员一致版本：
`git add -f uv.lock` 后提交（lockfile 较大 ~300KB，含全平台 hash）。

### 0.6 其他前置

- 数据库: `192.168.10.2:33066` 的 `evtrade` 库, `minute_bars` 表
  (`stock_code, stime, open, high, low, close, volume`)
  - 凭据可被环境变量 `EVTRADE_DB_URL` 整体覆盖, 默认值含密码, **不要提交到公开仓库**
- 时间: `stime` 为 14 位 `YYYYMMDDHHmmss` 字符串; 字典序即时间序
- 任意目录运行命令即可

## 2. 策略参数通用 dict 模式 (2026-09-09)

### 2.1 三种调用形式 (等价)

策略参数统一以 `dict[str, Any]` 传递 (兼容 kwargs):

```python
from evtrade.strategies import get_strategy

# 形式 1: dict 传入 (推荐, 适合 grid 扫描)
s = get_strategy("channel_deviation", params={"low1": 1.5, "low2": 1.0})

# 形式 2: kwargs 传入 (适合单次回测)
s = get_strategy("channel_deviation", low1=1.5, low2=1.0)

# 形式 3: 混合 (dict 优先, kwargs 填默认)
s = get_strategy("channel_deviation", params={"low1": 2.0}, low2=1.5)
```

### 2.2 策略声明参数 schema (`params_spec`)

每个策略类声明 `params_spec`, 基类自动**校验类型 + 默认值 + 范围**:

```python
from evtrade.strategies import VectorizedStrategy, register_strategy

@register_strategy("my_strategy")
class MyStrategy(VectorizedStrategy):
    params_spec = {
        "lookback":      {"default": 20,    "type": int,   "min": 2,    "max": 1000},
        "threshold_pct": {"default": 0.001, "type": float, "min": 0.0,  "max": 0.1},
    }

    def __init__(self, params=None, **kwargs):
        super().__init__(params=params, **kwargs)
        # self.params["lookback"] / self.params["threshold_pct"] 已可用

    def init_state(self, params):
        return {"lookback_ema": None}

    def step(self, state, bar, params):
        # 主入口: bar = {ts, o, h, l, c, v, mark} 单桶
        # 返回 (new_state, sig); sig ∈ {-1, 0, 1}
        if bar["mark"] == 0:
            return state, 0
        state["lookback_ema"], ema = ema_step(state["lookback_ema"], bar["c"], int(params["lookback"]))
        sig = 1 if bar["c"] > ema else (-1 if bar["c"] < ema else 0)
        return state, sig
```

> 策略只写一个 `step`；state 由 engine 持有跨调用（推荐 `@dataclass`）。指标用
> `from evtrade.indicators import ema_step`。完整范式见 14 号文档 §2 / 11 号文档 §3。

校验失败时报 `ValueError` (未声明 key / 超范围) / `TypeError` (类型错)。

## 5. 选参工作流：扫描 → 挑参 → 落盘 → 回测

四步闭环，每步一个 CLI 子命令，最优参数落盘到仓库内
`evtrade/strategies/_defaults/<strategy>.json`（默认跟踪，可分享），
单次回测/实盘不传参数即读默认。

### 5.1 网格扫描 (sweep)

```bash
python -m evtrade sweep \
  --strategy channel_deviation \
  --code 159992.SZ \
  --start 20250101 --end 20260903 \
  --grid low1=1.0,1.5,2.0,2.5 \
  --grid low2=0.5,1.0,1.5 \
  --grid high1=1.0,1.5,2.0,2.5 \
  --grid high2=0.3,0.5,0.8 \
  --device auto \
  --fee-bp 5 \
  --min-trades 30 \
  --max-mdd 0.4 \
  --score-lambda 1.0 \
  --splits 20250901 20260301 \
  --workers 8 \
  --out sweep_results.csv \
  --top 20
```

要点：

- `--device auto`：GPU（torch CUDA）可用则走 GPU，否则 CPU 降级 + warn。
- `--grid key=v1,v2,...` 可多次，笛卡尔积展开。
- `--splits ymd1 ymd2 ...`：滚动 WFO，列名带 `train_` / `test1_` / `test2_` 前缀。
- `--fee-bp / --min-trades / --max-mdd / --score-lambda`：评分
  `score = ann_net_min / (1 + λ·S)` 的过滤与权重（方法论见 13 号文档）。
- `--out`：结果 CSV 路径；`--top`：控制台预览前 N 组。

### 5.2 挑选最优参数

```bash
# 全表查看 (列太多时分页)
column -t -s, sweep_results.csv | less -S

# 按 test 段 score 排序取前 10
python -c "
import pandas as pd
df = pd.read_csv('sweep_results.csv')
print(df.sort_values('test1_score', ascending=False).head(10).to_string(index=False))
"
```

挑选原则：

- 优先看 `test1_score` / `test2_score`（实盘段），不只看 `train_score`。
- `test1_mdd` 不超 `--max-mdd` 阈值；`n_trades` 不低于 `--min-trades`。
- 若 `test1_score` 与 `train_score` 差距过大（过拟合），选更保守的那一组。

### 5.5 实盘接入

策略只出信号（`sig ∈ {-1,0,1}`），**不做具体买卖与成交**——成交决策在引擎/执行器层
（`trade_decision`，见 07 号文档）。实盘接入 = 换两处，其余不动：

1. **bar 流**：任意 `stream() -> Iterator[Bar]` 的对象（历史 + 实时拼接，
   `core/_harness.ListBarFeed` 是参考实现）；
2. **Executor**：自定义 `Executor` 子类，在其 `trade` 里接券商 API，回报到达后调
   `account.apply(side, qty, price, ts)`。

```python
# 实盘脚本骨架（示意; 信号 → 成交的边界见 07/11 号文档）
from evtrade.strategies._defaults_loader import load
from evtrade.strategies import get_strategy

params = load("channel_deviation")          # 不传参数 = 实盘默认 (落盘值)
strategy = get_strategy("channel_deviation", params=params)
# engine = Engine(bar_stream, aggregator, strategy, MyLiveExecutor(...))
# engine.run()
```

实盘机特定参数覆盖（不污染仓库）：

```bash

python -m evtrade params save channel_deviation \
  --params "low1:1.8;low2:1.2;high1:1.8;high2:0.6"
```

## 7. FAQ

**Q: 完全没有信号?**
确认预热充分 (`--period 1d` 且 start 前历史不足一年会导致指标就绪晚); 观察偏离量分布
(把 `--low1` 临时调小如 0.5 看是否开始出信号), 区分阈值过严 vs 数据/代码问题。

**Q: 信号时间戳为什么是 10:15 而我以为是 10:10~10:14 的行情?**
桶 ts 是前开后闭区间的右端点, `[10:15]` 桶覆盖 `(10:10, 10:15]`。详见 04 文档。

**Q: 能回测多个标的吗?**
单次运行单标的 (`load_bars` 按 `stock_code` 过滤)。多标的需循环调用或自行扩展
数据源 (见 11 文档)。

**Q: 如何改为实盘?**
换数据流 (任意 `stream() -> Iterator[Bar]` 对象, 历史+实时拼接) +
换 Executor (自定义 `Executor` 子类, 在其 `trade` 里接券商 API),
Engine/策略/账户不动。见 07、11 文档。

**Q: 中途 Ctrl+C 会丢汇总吗?**
vectorized 路径为一次性批量计算, Ctrl+C 直接中断 (未跑完无汇总)。
Engine 路径 `run()` 捕获 KeyboardInterrupt 后仍执行 `aggregator.flush()` +
末桶收尾, 基于已处理数据结束。

**Q: GPU 与 CPU 结果对不上?**
通常发生在 torch CUDA 不可用、auto 回退 cpu 时。显式传 `--device cpu` / `--device gpu` 排查;
`reconcile` 的 `bucket_diff_cap` 默认容忍 EMA 累积漂移 (≤8 桶), 超出需检查指标或策略代码。
