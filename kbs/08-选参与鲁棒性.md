# 08 选参与鲁棒性

> WFO(滚动窗口) + 邻域衰减 + 复合 score + 帕累托前沿
>
> 2026-09-13 起: framework 不汇总 PnL / 收益 / 风险指标(`metrics.summarize` 已下线)。
> 选参工作流跑通后, **绝对收益 / 风险调整**由策略代码自加字段查看
> (或自提供打印 hook); framework 仅在 sweep 输出"每窗 ann_net + score + filter_pass"三列
> 用于排序。本文档聚焦"凭什么说哪组参数最好"的方法论。
>
> 相关源码: `sweep.py` (`evtrade/core/sweep.py`)、`batched_sweep.py` (`evtrade/core/batched_sweep.py`)

## 1. 设计原则

**framework 不汇总 PnL, 选参口径在超额曲线上**(若有, 策略自提供)。

sweep 评分基于策略 step 末尾的 `state.primary_score`(策略自选标量, 默认 = `cash + position * price`,
即期末市值)。framework 只:
1. 逐窗跑 `run_vectorized`, 取 `state.primary_score`
2. 算每窗年化收益(`primary_score / years`)与最差窗(`min across windows`)
3. 算邻域衰减 S, 复合 score, 帕累托标记, filter_pass

策略若想看 Sharpe / 回撤 / 胜率, 自加 state 字段(如 `state.sharpe_curve / state.equity_curve`)
或自提供打印 hook。

## 2. 三层选参流程

### 2.1 第 1 层:硬过滤(`filter_pass` 列)

各 test 窗成交笔数 ≥ `--min-trades`(默认 30)——
笔数太少无统计意义。framework 维持这个硬过滤, 通过 `state.trades` 长度判定。

> `--max-mdd` / `--fee-bp` / `--mc` / `--mc-top` 已从 framework 删除(2026-09-13);
> 这些指标由策略自加字段, 自实现硬过滤。

### 2.2 第 2 层:主排序指标 `score`

```
每窗 primary 收益   primary_t = state.primary_score / years
最差窗口             primary_min = min(各 test 窗 primary_t)
邻域衰减 S           邻居(网格每轴 ±1 格)的平均 primary_min 相对自身的相对衰减, 截断到 [0,1]
                     (self ≤ 0 或无邻居 → 0; 孤立尖峰 → 1)
复合评分             score = primary_min / (1 + λ·S)      (primary_min ≤ 0 时原样透传)
```

- **取最差 test 窗而不是均值**: 单窗冠军大概率是运气; 在最不利验证段也不亏的参数才能上实盘。
- **score 在 `primary_min ≤ 0` 时直接透传**(不除 `1 + λ·S`): 负收益的"邻域衰减惩罚"无意义,
  让负分靠拢原值排序, 靠 `filter_pass` / 帕累托进一步筛选。
- **λ (`--score-lambda`, 默认 1)**: 稳健偏好旋钮。λ 越大越偏向"参数平原中心"。
- **帕累托 (`pareto` 列)**: (primary_min_mean, primary_min_std) 双目标非支配点 —
  收益与平稳性的前沿集合; 激进选前沿上收益最高者, 稳健选平原中心(S 小)者。

> **score 公式的迁移**: 旧版基于 `ann_net_min`(扣费年化超额 + 邻域衰减) +
> 手续费/回撤硬过滤; 现版基于 `primary_min` + `state.primary_score` 策略自选标量 +
> 笔数硬过滤。方法论不变, 输入由策略提供。

### 2.3 第 3 层:显著性检验

2026-09-13 起 `--mc N` / `--mc-top` 已从 framework 删除。显著性检验若需要,
由策略在 sweep 后**自行跑置换**(调 `numpy.random` 打乱价格路径, 重放 step, 收集 null 分布)。
文档示例可参考 [archive/DSL-HISTORY](archive/DSL-HISTORY.md) 时期的历史方案。

## 3. 用法

```bash
# CPU 标准网格扫描
python -m evtrade sweep --strategy channel_deviation --device cpu \
    --code 159992.SZ \
    --start 20250101 --end 20260903 \
    --grid "low1=1.2,1.5,2.5" --grid "low2=0.3,0.5,0.8" \
    --grid "high1=1.2,1.5,2.5" --grid "high2=0.3,0.5,0.8" --grid "tf1=10,21,60" \
    --splits 20260101,20260401,20260701 \
    --score-lambda 1.0 \
    --out results_robust.csv

# GPU 大网格自动走 batched (ma_crossover)
python -m evtrade sweep --strategy ma_crossover --device gpu \
    --grid "fast=5,10,15,20,25,30,40,50,60,80" \
    --grid "slow=20,30,40,50,60,80,100,120,160,200" \
    --splits 20260101,20260401 --out results.csv

# 合成数据无库体验
python -m evtrade sweep --strategy channel_deviation --synthetic-days 120 \
    --start 20250601 --end 20260101 --device cpu \
    --grid "low1=0.4,0.6,0.8"

# 跑完按 score 选最优行 + 落盘 + git commit
python -m evtrade sweep --strategy channel_deviation \
    --grid "low1=1.0,1.5,2.0" --grid "high2=0.3,0.5,0.8" \
    --splits 20250901 20260301 --save-defaults
```

窗口划分(`--splits d1,d2,d3`): train=[start,d1) + test1=[d1,d2) + test2=[d2,d3) +
test3=[d3,end]。每个 test 窗以**其开始日之前的全部数据**做指标预热、锁存状态全新起算——
与实盘在该日上线的情形一致。单 `--split` 等价 `--splits` 单值(列名 train/test)。

输出列(框架提供):
- 每窗 `state.primary_score`(`primary_t1` / `primary_t2` / ...)
- `primary_min` / `primary_mean` / `pos_ratio`
- `S`(邻域衰减) / `score`(主排序) / `pareto`(是否前沿)
- `filter_pass`(硬过滤是否通过)

按 score 降序。

## 4. 实例解读(159992.SZ)

按 score 前 3 名(全部 tf1=60, high1=1.2, high2=0.8):

| low1/low2 | primary_min | primary_mean | pos_ratio | S | score | 备注 |
|---|---|---|---|---|---|---|
| 1.2/0.5 | +4.84%/年 | +6.27%/年 | 1.0 | 0.32 | 3.68 | 在最差窗也正收益 |
| 2.5/0.5 | +5.66%/年 | +5.82%/年 | 1.0 | 0.57 | 3.62 | 邻域衰减略大 |
| 1.2/0.8 | +5.27%/年 | +7.72%/年 | 1.0 | 0.48 | 3.56 | 平原中心附近 |

诚实信号解读:

- score 前 3 名仅说明在网格内相对稳健, **不代表绝对可实盘**。
- 策略在该标的上若绝对收益为负(train 窗负 + test 窗正),
  score 仍可能高(因为 score 用的是 `primary_min` 而非绝对值)。
- 参数区**跨标的不可直接迁移**: 159992.SZ 选出的 tf1=60/high1=1.2 家族 ≠ 513120.SH 最佳家族,
  必须逐一验证。

## 5. GPU 批量路径(opt-in)

`--device gpu` + `ma_crossover` + 网格 ≥32 组 → 自动走 batched 路径
(`MACrossoverStrategy.batched_step` 一次出 `[N, T]` 信号);
其它策略 / 小网格 / 无 CUDA / `--device cpu` 仍走 `ThreadPoolExecutor` + `--workers` 多进程。
score / S / pareto / filter_pass 定义不变。

详见 [07-PyTorch与性能 §Batched sweep hook](07-PyTorch与性能.md)。

## 6. 落盘默认参数(选参工作流的最后一环)

```bash
# 方式 a: 直接从 --params 字符串存
python -m evtrade params save channel_deviation \
  --params "low1:1.5;low2:1.0;high1:1.5;high2:0.5"

# 方式 b: 从 sweep 结果 CSV 取第 N 行(1 = score 最高)
python -m evtrade params save channel_deviation \
  --from-csv sweep_results.csv --rank 1

# 查看 / 列出
python -m evtrade params show channel_deviation
python -m evtrade params list
```

落盘文件 `evtrade/strategies/_defaults/<strategy>.json`:

```json
{
  "strategy": "channel_deviation",
  "params": {"low1": 1.5, "low2": 1.0, "high1": 1.5, "high2": 0.5},
  "saved_at": "2026-09-07T00:00:00+00:00",
  "source": {"kind": "from_csv", "csv": "sweep_results.csv", "rank": 1}
}
```

单次回测 / 实盘不传 `--params` 即自动读默认:

```bash
# 不传 --params; 自动从 _defaults/channel_deviation.json 读
python -m evtrade backtest --strategy channel_deviation \
  --code 159992.SZ --start 20260101 --end 20260903 --device auto
```


## 7. 已知边界

- `state.primary_score` 默认 = `cash + position * price`(期末市值), 由策略自选;
  若想看 Sharpe / 回撤 / 胜率, 自加 state 字段。
- score 只在**给定网格内**比较; 网格本身的设计(轴与步长)决定搜索空间。
- 该框架衡量"历史择时在多窗下的稳健性", 不能预测未来体制切换。
- 旧版"置换检验显著性"已从 framework 删除; 若需要, 策略可自实现 numpy 打乱价格路径重放 step。
- vectorized 引擎无 numba JIT, 单组回测吞吐比旧内核慢; 大网格扫描建议 `--workers 16` +
  `--device auto` 以保证吞吐。
