# 13 绩效评估与鲁棒选参框架

> 回答的问题: 批量回测后, **凭什么说哪组参数"最好"**。
> 本框架已固化进 `evtrade/core/sweep.py` + `evtrade/core/permutation.py` + `vectorized_engine.run_vectorized` (CPU/GPU 统一),
> 由 `tests/test_strategy_unified.py` + `tests/test_sweep_v2.py` 等锁定。

## 1. 设计原则: 只衡量"择时贡献", 剥离行情本身

账户结构是 20 万股底仓 + 每笔 1 万股, 权益曲线 ≈ 买入持有 ± 小幅择时扰动。
因此**权益曲线的 Sharpe/回撤主要由标的 β 决定**, 几乎不随参数变化, 不能用来选参。
所有选参口径定义在**超额曲线**上:

```
逐 bar 超额率:  x_t = (策略权益_t − 基线权益_t) / 基线权益_t
基线权益_t    = 期初资金 + 期初持仓 × 现价_t      (即"什么都不做")
```

`vectorized_engine._execute_trades` 逐 bar 累积 `equity_curve` 与 `baseline_curve`,
末尾调 `metrics.summarize(equity_curve, baseline_curve, years, n_trades, n_buy, n_sell, turnover, ...)` 算全套字段:

| 指标 | 定义 | 回答的问题 |
|---|---|---|
| `cagr` | 策略权益年化增速 | 择时贡献的年化速度 |
| `sharpe / sharpe_excess` | 日频收益 / 超额曲线的夏普 | 择时贡献平稳还是靠几笔大单 |
| `sortino / sortino_excess` | 下半方差 Sharpe (penalize 下行) | 同上, 排除上行波动 |
| `calmar` | cagr / max_drawdown | 收益/回撤比 |
| `max_dd_days` | 最大回撤持续天数 | 回撤多久能爬出来 |
| `max_dd_recovered` | 最大回撤恢复天数 | 回撤后是否真正创新高 |
| `max_drawdown` | 权益曲线最大回撤幅度 | **只作硬约束** (实盘承受度), 不参与排序 |
| `years` | 首末策略期 bar 自然日差 / 365.25 | 跨窗口可比的年化分母 |

> **2026-09-09 变化**: 旧版 `ann_excess_pct / sharpe_excess / x_mdd` 三个内核字段被 `cagr / sharpe / sharpe_excess / sortino / calmar / max_dd_days / max_dd_recovered / max_drawdown` 8 个 metrics 字段取代;
> 字段由 `metrics.summarize` 统一计算 (vectorized_engine 调用), 内核 (kernel) 已删除, 扫描路径全部走 vectorized。

## 2. 三层选参流程

### 第 1 层: 硬过滤 (`filter_pass` 列, 不满足直接出局)
- 各 test 窗成交笔数 ≥ `--min-trades` (默认 30) —— 笔数太少无统计意义
- 各 test 窗权益回撤 ≤ `--max-mdd` (默认 1.0 即不设限; 实盘建议 0.15)

### 第 2 层: 主排序指标 `score`
```
每窗年化扣费超额  ann_net = cagr/years − turnover×fee/baseline/years×100
最差窗口          ann_net_min = min(各 test 窗 ann_net)
邻域衰减 S        邻居(网格每轴 ±1 格)的平均 ann_net_min 相对自身的相对衰减, 截断到 [0,1]
                  (self≤0 或无邻居 → 0; 孤立尖峰 → 1)
复合评分          score = ann_net_min / (1 + λ·S)      (ann_net_min≤0 时原样透传)
```
- **取最差 test 窗而不是均值**: 单窗冠军大概率是运气; 在最不利验证段也不亏的参数才能上实盘。
- **λ (`--score-lambda`, 默认 1)**: 稳健偏好旋钮。λ 越大越偏向"参数平原中心"。
- **费率 (`--fee-bp`, 默认 5bp)**: 直接进主指标, 堵住高频参数的幻觉。
- **帕累托 (`pareto` 列)**: (ann_net_mean, sharpe_min) 双目标非支配点 —— 收益与平稳性的
  前沿集合; 激进选前沿上收益最高者, 稳健选平原中心 (S 小) 者。

### 第 3 层: 显著性检验 (`--mc N`, 蒙特卡洛日块置换)
- 对 score 前 `--mc-top` 名, 把价格路径按**自然日整块**打乱重跑 N 次, 得到
  "无多日结构"null 下的年化超额分布, 报告真实值的 p 值。
- 统计量用**费前**年化超额: 费用已由 ann_net 单独衡量; null 若含费用会被
  "交易频率差异"主导而失真。
- **为什么按日打乱而不是逐 bar**: 实测逐 bar 打乱会制造剧烈人工跳变, 触发条件
  (H 回到下轨 / L 回到上轨) 在随机数据上系统性"买贵卖贱" (买入均价 0.789 vs
  卖出 0.755), null 被打穿到 -60%/年, 完全失去参考价值。日块打乱保留日内微观
  结构, null 恢复理性 (-12%~-14%/年, 且有合理方差)。
- **解读纪律**: p 小只说明"显著好于无结构运气", 是必要条件而非充分条件;
  绝对收益为负时 (见下文实例) 依然不可用。

## 3. 用法

```bash
python -m evtrade sweep --strategy channel_deviation --code 159992.SZ \
    --start 20250101 --end 20260903 --device auto \
    --data-cache cache \
    --grid "low1=1.2,1.5,2.5" --grid "low2=0.3,0.5,0.8" --grid "high1=1.2,1.5,2.5" \
    --grid "high2=0.3,0.5,0.8" --grid "tf1=10,21,60" \
    --splits 20260101,20260401,20260701 \
    --fee-bp 5 --score-lambda 1.0 --min-trades 30 --max-mdd 0.15 \
    --mc 300 --mc-top 5 \
    --out results_robust.csv
```

窗口划分 (`--splits d1,d2,d3`): train=[start,d1) + test1=[d1,d2) + test2=[d2,d3) +
test3=[d3,end]。每个 test 窗以**其开始日之前的全部数据**做指标预热、锁存状态全新
起算 —— 与实盘在该日上线的情形一致。单 `--split` 等价 `--splits` 单值 (列名 train/test)。

输出列: 每窗原始指标 (`train_*`, `test1_*`...) + 每窗 `ann_net` + 聚合列
(`ann_net_min/ann_net_mean/pos_ratio/sharpe_min/x_mdd_max/S/score/pareto/filter_pass`),
按 score 降序。

## 4. 实例解读 (159992.SZ, 243 组, 3 窗 WFO + 5bp)

按 score 前 3 名 (全部 tf1=60, high1=1.2, high2=0.8):

| low1/low2 | ann_net_min | ann_net_mean | pos_ratio | sharpe_min | S | score | MC p 值 |
|---|---|---|---|---|---|---|---|
| 1.2/0.5 | +4.84%/年 | +6.27%/年 | 1.0 | 0.65 | 0.32 | 3.68 | 0.02 |
| 2.5/0.5 | +5.66%/年 | +5.82%/年 | 1.0 | 0.27 | 0.57 | 3.62 | 0.03 |
| 1.2/0.8 | +5.27%/年 | +7.72%/年 | 1.0 | 1.15 | 0.48 | 3.56 | 0.01 |

注意的诚实信号: 该家族**全周期费前年化超额其实为负** (train 窗 2025 年为负,
test 窗 2026 年为正), MC 的 p=0.01~0.03 说明它"显著好于无结构运气", 但绝对收益
为负 → 在 159992 上仍不可直接实盘。513120.SH 同框架重扫, score 头部为
tf1=10/60 + high1=1.2 + high2=0.8 家族 (ann_net_min +7%/年, pos_ratio=1.0)。
**结论与 06/12 号文档一致: 参数区跨标的不可直接迁移, 必须逐一验证。**

## 5. 已知边界

- 单次 MC 的 p 值受置换次数影响 (默认 200~300, 发论文级结论建议 1000+)。
- 日块打乱仍保留块边界上的人工跳变 (隔夜缺口放大), 属标准 block-bootstrap 误差。
- score 只在**给定网格内**比较; 网格本身的设计 (轴与步长) 决定搜索空间。
- 该框架衡量"历史择时在多窗/多扰动下的稳健性", 不能预测未来体制切换。
- vectorized 引擎现在不带 numba JIT, 单组回测吞吐比旧内核慢; 大网格扫描建议 `--workers 16` + `--device auto`
  以保证吞吐。
