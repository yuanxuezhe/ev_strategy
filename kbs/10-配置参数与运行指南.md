> 相关源码：`evtrade/cli.py`（backtest / sweep / params 三个子命令，2026-09-13 删 replay）；
> framework 不再持有资金/撮合/PnL 概念，相关参数走策略 `--params`。

## 1. 命令行结构

```
python -m evtrade backtest [参数]    # 单次回测 (framework 仅驱动 step)
python -m evtrade sweep    [参数]    # 参数并发扫描 + 鲁棒评分 (见 13 号文档)
python -m evtrade params   [子命令]    # 默认参数管理 (落盘 evtrade/strategies/_defaults/)
```

### backtest 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--period` | `5m` | K 线周期，**任意 数字+m/h/d**：5m/7m/90m/2h/4h/6h/1d/3d... |
| `--start` | `20250101` | 策略起始日期 YYYYMMDD |
| `--end` | `20260903` | 策略结束日期 YYYYMMDD |
| `--strategy` | `channel_deviation` | 策略 key（注册表名） |
| `--params` | (策略默认) | 策略参数 `k1:v1;k2:v2`（按 `params_spec` 校验）。**资金/撮合参数**如 `init_cash`/`init_position`/`trade_qty`/`buy_pct`/`sell_pct` 全部走 `--params` |
| `--device` | `auto` | **统一参数**：`cpu` (torch CPU) / `gpu` (torch CUDA) / `auto` (gpu 可用则 gpu) |
| `--code` | `159992.SZ` | 证券代码（示例：`159992.SZ` / `513120.SH`） |
| `--verbose` | 关 | 逐根打印策略 `format_signal_line` 输出（sig!=0 时） |
| `--synthetic-days` | 0 | >0 时用合成数据（不连库，无库体验） |
| `--signals-out` | 无 | 信号轨迹 CSV (ts,sig) |

> **2026-09-13 变化**：framework 删 `--init-cash --init-position --buy-pct --sell-pct --all-in --trade-qty --warmup-days --data-cache --fee-bp`（funding/撮合 由策略 `--params` 承担）。需要查看策略资金/持仓/账本请在策略代码内自己加 `print` 或 hook。

> **2026-09-10 变化**: 删 `--tf1` / `--low1` / `--low2` / `--high1` / `--high2` CLI 参数；
> 策略私有参数（如 tf1、low1/low2/high1/high2）一律经 `--params "k1:v1;k2:v2"` 传入。

### 策略参数解析优先级（高 → 低）

每条命令解析策略参数时按以下顺序：

1. **`--params "k:v;..."`** 显式传入（任何策略，类型自动推导 int/float/bool/str）
2. **`evtrade/strategies/_defaults/<strategy>.json`** 落盘默认（`params save` 写入）
3. **空 dict** → `VectorizedStrategy.params_spec` 的 `default` 值

实盘/CI 机器用 `EVTRADE_DEFAULTS_DIR` 环境变量切换落盘目录，不污染仓库。

### sweep 参数（评分语义见 13 文档）

`--grid "名字=v1,v2"`（可多次；仅接受策略 `params_spec` 内的参数名，引擎轴仅剩 `period`）、
`--splits d1,d2,d3`（滚动 WFO 窗）、`--split d`（单窗，兼容旧名）、
`--score-lambda 1.0`、`--workers`、`--device cpu|gpu|auto`、`--synthetic-days N`（无库体验）、
`--out`、`--top`、`--save-defaults`（跑完自动按 score 选最优行 + 落盘
`evtrade/strategies/_defaults/<strategy>.json` 并 git commit；与 `--no-save-defaults` 互斥）。

> `--device` 在 sweep 中决定每组参数批量回测的后端 (cpu/gpu)。
> `--device gpu` + `ma_crossover` + 网格 ≥32 组会自动走 batched 单次 kernel
> 路径（见 [15-PyTorch统一策略.md §7.4](15-PyTorch统一策略.md)），该模式下
> `--workers` 被忽略（打印 notice）；其它策略 / 小网格仍走 `--workers` CPU 多线程。
> batched 路径仅产 sig，cash/position 由 sweep 串行 step 补。

> **2026-09-13 变化**：删 `--fee-bp --min-trades --max-mdd --mc --mc-top`（funding/收益/置换 由策略自管）。
> 策略可在自己 step 内加 PnL/收益/绩效计算（需要的话后期再加）。

## 2. 典型命令

```bash
# 安装依赖 (torch 为统一 CPU/GPU 后端)
pip install pymysql sqlalchemy pandas torch

# 标准 CPU 全速回测
python -m evtrade backtest --strategy channel_deviation --device cpu \
    --period 5m --start 20250101 --end 20260903

# GPU 回测（需 torch CUDA 版 wheel；无 CUDA 时 --device gpu 抛错，用 --device auto 自动降级）
python -m evtrade backtest --strategy channel_deviation --device auto \
    --period 5m --start 20250101 --end 20260903

# GPU 机器一次性安装 (RTX 50 / Blackwell 需 cu128)
uv sync --extra gpu              # 锁住 torch==2.9.0+cu128
bash scripts/sync-torch-cu.sh    # 防御性 helper (lockfile 被 uv 重生时恢复)

# 小段快速验证参数 (含资金/撮合参数, 全部走 --params)
python -m evtrade backtest --strategy channel_deviation \
    --params "tf1:21;low1:1.0;init_cash:200000;trade_qty:10000" \
    --period 5m --start 20250601 --end 20250901

# 换标的 + 1 小时周期 + 更苛刻的偏离阈值
python -m evtrade backtest --strategy channel_deviation --code 513120.SH \
    --period 1h --params "low1:2.0;low2:1.2;high1:2.0;high2:0.8"

# 无库体验 (合成数据)
python -m evtrade backtest --strategy channel_deviation --synthetic-days 120 \
    --period 5m --start 20250601 --end 20250701
```

## 3. 运行前检查清单

1. 网络可达 `192.168.10.2:33066`，账号 `EvTrade` 可读 `evtrade` 库（`DB_URL` 在 `core/data.py` 默认，可环境变量 `EVTRADE_DB_URL` 覆盖）
2. `minute_bars` 表中存在目标 `stock_code`、且覆盖 `[start-prewarm, end]` 的数据
3. `stime` 列建议有索引（`_fetch` 单次全量 SQL 按 `stime` 范围 + `stock_code` + 排序）
4. `low1 > low2`、`high1 > high2`（否则锁存失效）；参数经 `_resolve_params` 按 `params_spec` 校验
5. 数据量估算：1 年 1m ≈ 24 万根/标的（交易时段），乘以回测年数；首次运行留意磁盘与内存
6. GPU 路径需 `torch`（CUDA 版 wheel）；缺失时 `--device gpu` 抛错（提示改用 `auto`/`cpu`），`--device auto` 自动降级 cpu 并打 warning

## 4. 输出解读

### 4.1 数据加载进度（load_bars 打印）

```
  -- 加载 614400 根 1m bar [20240102 ~ 20260903] (含预热)
```

数据由 `core/data.load_bars` **单次全量拉取**（一次 `fetchall` 后本地处理，不再分段查询）。
长时间卡在加载 = SQL 慢（查 `stime` 索引）。

### 4.2 信号行（Engine / run_vectorized 打印，仅有信号时）

```
BUY  >>> [20250106101500] | UP=1.2345 DW=1.2340 | low_dev(L/DW)=2.31% high_dev(H/UP)=0.45%
```

- 时间戳 = **桶 CLOSE 时的桶右端点 ts**（与 vectorized 路径同口径）。
- 数值按 4 位小数显示（`fmt` 函数）。
- 2026-09-13 重构：framework 不再 print 成交明细；策略要看成交/资金请自己加 print 或 hook。

### 4.3 框架输出（仅驱动 step）

2026-09-13 重构后 framework 不再汇总 PnL/收益/回撤/胜率等任何业务字段。
`run_vectorized` 返回 = `{sig, buckets, final_state}`：

```
回测完成 (vectorized; 仅驱动 step; framework 不汇总 PnL/收益)
============================================================
信号轨迹:    498 桶 (mark=1 段)
桶数:        500 (含预热)
引擎耗时:    1234.5 ms (24000 根 1m bar, cpu)
------------------------------------------------------------
策略 final_state (framework 仅透传):
  ema = <EMAChannelState>
  fsm = <DeviationFSM>
  cash = 0.0
  position = 16671.6
  trades = <list>
```

要看 PnL/收益/绩效请在策略 step / state 内自加字段，框架不输出。

## 5. 常见问题

- Q: 旧 `--init-cash` / `--buy-pct` 等还在吗？
  A: 已删除（2026-09-13）。走 `--params "init_cash:100000;trade_qty:10000;buy_pct:0.5"` 传。

- Q: 想看收益、绩效？
  A: framework 不再做。策略代码内自己加 state 字段（如 `equity_curve` / `cagr` / `sharpe`），或自己提供打印 hook。

- Q: replay 子命令 / `--against-ref` 还在吗？
  A: 已删除（2026-09-13）。framework 不再做对账。
