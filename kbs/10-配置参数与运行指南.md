# 10 配置参数与运行指南

> 相关源码：`evtrade/cli.py`（backtest / sweep / replay / params 四个子命令）、常量（`evtrade/core/config.py`）。
> 本文档 2026-09-09 随统一 CPU/GPU 重构更新（删 `--engine`，统一 `--device`）；评分/选参方法论见 13 号文档。

## 1. 命令行结构

```
python -m evtrade backtest [参数]    # 单次回测
python -m evtrade sweep    [参数]    # 参数并发扫描 + 鲁棒评分 (见 13 号文档)
python -m evtrade replay   [参数]    # 录制回放对账 (实盘一致性验收)
```

### backtest 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--period` | `5m` | K 线周期，**任意 数字+m/h/d**：5m/7m/90m/2h/4h/6h/1d/3d... |
| `--start` | `20250101` | 策略起始日期 YYYYMMDD（**之前 365 天自动作为预热**） |
| `--end` | `20260903` | 策略结束日期 YYYYMMDD |
| `--strategy` | `channel_deviation` | 策略 key（注册表名） |
| `--params` | (策略默认) | 策略参数 `k1:v1;k2:v2`（按 `params_spec` 校验） |
| `--device` | `auto` | **统一参数**：`cpu` (torch CPU) / `gpu` (torch CUDA) / `auto` (gpu 可用则 gpu) |
| `--trade-qty` | 10000 | 每次信号交易股数 |
| `--all-in` | 关 | 全仓模式（等价 `--buy-pct 1.0 --sell-pct 1.0`） |
| `--buy-pct` | 0.0 | BUY 时按当前现金的该比例下注（0=关闭走 `--trade-qty`） |
| `--sell-pct` | 0.0 | SELL 时按当前持仓的该比例卖（0=关闭走 `--trade-qty`） |
| `--code` | `159992.SZ` | 证券代码（示例：`159992.SZ` / `513120.SH`） |
| `--verbose` | 关 | 逐根打印策略 `format_signal_line` 输出（sig!=0 时） |
| `--warmup-days` | 365 | 预热天数（拉取 start 之前的行情供指标就绪） |
| `--warmup-until` | 无 | 预热截止时刻 YYYYMMDHMMSS（replay 用） |
| `--data-cache` | 无 | 行情 npz 缓存目录（命中后不访问数据库） |
| `--synthetic-days` | 0 | >0 时用合成数据（不连库，无库体验） |
| `--init-cash` | 200000 | 期初资金（默认 20 万）；传 0 忽略，走零起点 |
| `--init-position` | 200000 | 期初持仓股数（默认 20 万）；传 0 忽略，走零起点 |
| `--fee-bp` | 5.0 | 手续费（bps） |
| `--from-csv` | 无 | params 子命令：从 CSV 读参数 |
| `--signals-out` | 无 | 信号轨迹 CSV (ts,sig) |
| `--out` | 无 | sweep 结果 CSV 输出路径 |

> **2026-09-09 变化**: 删 `--engine {kernel, ref, vectorized}`（已物理移除，无兼容层）；
> 后端选择统一用 `--device {cpu, gpu, auto}`。

代码内常量（不在命令行暴露）：`DB_URL`（环境变量 `EVTRADE_DB_URL` 可覆盖）、
`TABLE=minute_bars`、`INIT_CASH=200000`、`INIT_POSITION=200000股`。

> **2026-09-10 变化**: 删 `--tf1` / `--low1` / `--low2` / `--high1` / `--high2` CLI 参数；
> 策略私有参数（如 tf1、low1/low2/high1/high2）一律经 `--params "k1:v1;k2:v2"` 传入。

### 策略参数解析优先级（高 → 低）

每条命令解析策略参数时按以下顺序：

1. **`--params "k:v;..."`** 显式传入（任何策略，类型自动推导 int/float/bool/str）
2. **`evtrade/strategies/_defaults/<strategy>.json`** 落盘默认（`params save` 写入）
3. **空 dict** → `VectorizedStrategy.params_spec` 的 `default` 值

实盘/CI 机器用 `EVTRADE_DEFAULTS_DIR` 环境变量切换落盘目录，不污染仓库。

### sweep 参数（评分语义见 13 文档）

`--grid "名字=v1,v2"`（可多次；支持 period/trade_qty/buy_pct/sell_pct，及策略 `params_spec` 内的参数名如 tf1/low1/high2）、
`--splits d1,d2,d3`（滚动 WFO 窗）、`--split d`（单窗，兼容旧名）、`--fee-bp 5`、
`--score-lambda 1.0`、`--min-trades 30`、`--max-mdd`、`--mc 300`、`--mc-top 5`、
`--workers`、`--device cpu|gpu|auto`、`--synthetic-days N`（无库体验）、`--out`、`--top`、
`--save-defaults`（跑完自动按 score 选最优行 + 落盘 `evtrade/strategies/_defaults/<strategy>.json` 并 git commit；与 `--no-save-defaults` 互斥）。

> `--device` 在 sweep 中决定每组参数批量回测的后端 (cpu/gpu)。
> `--device gpu` + `ma_crossover` + 网格 ≥32 组会自动走 batched 单次 kernel
> 路径（见 [15-PyTorch统一策略.md §7.4](15-PyTorch统一策略.md)），该模式下
> `--workers` 被忽略（打印 notice）；其它策略 / 小网格仍走 `--workers` CPU 多进程。

### replay 参数

`--log`（bar 日志 CSV）、周期与策略参数同 backtest、`--warmup-until YYYYMMDHMMSS`、
`--against-ref`（同时用参考引擎回放并逐 bar 对账，输出 PASS/FAIL + 分歧统计）、
`--signals-out`（信号轨迹 CSV，桶级 ts/sig 逐对）。日志由 `evtrade.replay.append_bar / write_bars_log` 产生（实盘侧每根 bar 追加一行）。

> `--against-ref` 内部调 `evtrade.core.replay.reconcile`：
> vectorized vs Engine.on_bars 桶级信号 + 逐笔成交 bitwise 对账。
> 默认 `bucket_diff_cap=8`（lenient），`EVT_RECONCILE_STRICT=1` 时 cap=0（strict）。

## 2. 典型命令

```bash
# 安装依赖 (torch 为统一 CPU/GPU 后端)
pip install pymysql sqlalchemy pandas torch

# 标准 CPU 全速回测
python -m evtrade backtest --strategy channel_deviation --device cpu \
    --period 5m --start 20250101 --end 20260903

# GPU 回测（需 torch CUDA 版 wheel；无 CUDA 时 --device gpu 抛错，用 --device auto 自动降级）
python -m evtrade backtest --strategy channel_deviation --device auto \
    --period 5m --start 20250101 --end 20260903

# GPU 机器一次性安装 (RTX 50 / Blackwell 需 cu128)
uv sync --extra gpu              # 锁住 torch==2.9.0+cu128
bash scripts/sync-torch-cu.sh    # 防御性 helper (lockfile 被 uv 重生时恢复)

# 小段快速验证参数
python -m evtrade backtest --strategy channel_deviation --params "tf1:21;low1:1.0" \
    --period 5m --start 20250601 --end 20250901

# 换标的 + 1 小时周期 + 更苛刻的偏离阈值
python -m evtrade backtest --strategy channel_deviation --code 513120.SH \
    --period 1h --params "low1:2.0;low2:1.2;high1:2.0;high2:0.8"

# 无库体验 (合成数据)
python -m evtrade backtest --strategy channel_deviation --synthetic-days 120 \
    --period 5m --start 20250601 --end 20250701

# 回放对账
python -m evtrade replay --log /tmp/demo.log --strategy channel_deviation \
    --device cpu --against-ref
```

## 3. 运行前检查清单

1. 网络可达 `192.168.10.2:33066`，账号 `EvTrade` 可读 `evtrade` 库（`DB_URL` 在 `core/config.py` 硬编码，属敏感信息）
2. `minute_bars` 表中存在目标 `stock_code`、且覆盖 `[start-365天, end]` 的数据
3. `stime` 列建议有索引（`_fetch` 单次全量 SQL 按 `stime` 范围 + `stock_code` + 排序）
4. `low1 > low2`、`high1 > high2`（否则锁存失效）；参数经 `_resolve_params` 按 `params_spec` 校验
5. 数据量估算：1 年 1m ≈ 24 万根/标的（交易时段），乘以回测年数；首次运行留意磁盘与内存
6. GPU 路径需 `torch`（CUDA 版 wheel）；缺失时 `--device gpu` 抛错（提示改用 `auto`/`cpu`），`--device auto` 自动降级 cpu 并打 warning

## 4. 输出解读

### 4.1 数据加载进度（load_bars 打印）

```
  -- 缓存命中: cache/159992.SZ_20240102_20260903.npz (614400 根)
  -- 加载 614400 根 1m bar [20240102 ~ 20260903] (含预热)
```

数据由 `core/data.load_bars` **单次全量拉取**（一次 `fetchall` 后本地处理，不再分段查询）；
开启 `--data-cache` 后按 `(code, 预热起点, end)` 键命中 npz 缓存，命中则零数据库开销。
长时间卡在加载 = SQL 慢（查 `stime` 索引）。

### 4.2 信号行（Engine 打印，仅有信号时）

```
BUY  >>> [20250106101500] | UP=1.2345 DW=1.2340 | low_dev(L/DW)=2.31% high_dev(H/UP)=0.45%
```

- 时间戳 = **桶 CLOSE 时的桶右端点 ts**（与 vectorized 路径同口径）。
- 数值按 4 位小数显示（`fmt` 函数）。
- **Engine 路径不再实时打印成交明细**（2026-09-12 cleanup；`SimulatedExecutor` 仅调 `trade_decision` + `Account.apply`，不 print）。成交可见输出走 CLI 回放：`backtest --verbose` 末尾从 `summary['trades']` 打；`replay --signals-out <file>` 写 csv。

### 4.3 盈亏汇总

盈亏汇总统一由 `metrics.summarize` 计算（vectorized / Engine 两条路径同一口径），CLI 打印 30 字段（2026-09-10 扩展）:
```
============ 回测盈亏汇总 (vectorized / cpu) ============
[终态]    final_price / final_cash / final_position / final_equity / baseline
[交易]    n_trades / n_buy / n_sell / turnover / excess_pct
[时间]    years / cagr_excess
[风险调整] cagr / sharpe_excess / sortino_excess / calmar / ir
[回撤]    max_drawdown / max_dd_days / max_dd_recovered / x_mdd
[持仓行为] win_rate / profit_factor / avg_pnl
          max_consecutive_wins / max_consecutive_losses
          avg_hold_bars / max_hold_bars
[基准对比] baseline_max_dd / dd_excess
```

> `max_dd_recovered` 未恢复时 = -1 (sentinel); `profit_factor` 无亏损时 = inf。

- 盈亏为正 = 择时跑赢"拿着不动"；未扣手续费/滑点。
- 交易次数为 0 也正常（区间内没出现"极端偏离→回撤"完整过程）。
- 详细字段定义见 [13-绩效评估与鲁棒选参框架.md](../13-绩效评估与鲁棒选参框架.md)。

## 5. 性能建议

| 手段 | 效果 |
|---|---|
| `--device gpu` | GPU 路径用 torch CUDA 算子；CUDA 不可用时抛错（改用 `--device auto` 自动降级 cpu + warning） |
| `--data-cache cache` | npz 缓存命中后二次运行零数据库开销 |
| 先 `--start/--end` 小区间调参 | 快速迭代阈值后再拉长区间 |
| 确认 `stime` 索引 | 单次全量范围查询是取数瓶颈所在 |

## 6. FAQ

**Q: 完全没有信号？**
先确认预热充分（`--period 1d` 且 start 前历史不足一年会导致指标就绪晚）；再观察偏离量分布——把 `--params "low1:0.5"` 临时调小（如 0.5）看是否开始出信号，判断是阈值过严还是数据/代码问题。

**Q: 信号时间戳为什么是 10:15 而我以为是 10:10~10:14 的行情？**
桶 ts 是前开后闭区间的右端点，`[10:15]` 桶覆盖 `(10:10, 10:15]`。详见 04 文档。

**Q: 能回测多个标的吗？**
单次运行单标的（load_bars 按 `code` 过滤）。多标的需循环调用或自行扩展 bar 流（见 11 文档）。

**Q: 如何改为实盘？**
换 bar 流（自定义 `.stream()` 对象，历史预热 + 实时）+ 换 Executor（自定义 `Executor` 子类接券商 API），Engine/策略/账户不动。见 07、11 文档。

**Q: 中途 Ctrl+C 会丢汇总吗？**
不会。`metrics.summarize` 基于已加载的全量数据出汇总（数据由 `load_bars` 一次性拉取，中断时未拉取的后续区间自然缺失）。

**Q: GPU 与 CPU 结果对不上怎么办？**
通常发生在 `--device auto` 在 CUDA 不可用机器上降级 cpu（与显式 gpu 对比时）。显式传 `--device cpu` / `--device gpu` 排查；reconcile 的 `bucket_diff_cap` 默认容忍 EMA 累积漂移（≤8 桶），超出需检查指标实现或策略代码。

**Q: 旧脚本里的 `--engine kernel/ref/vectorized` 还能用吗？**
不能，`--engine` 已物理移除（含兼容层）。后端选择一律用 `--device {cpu, gpu, auto}`。
