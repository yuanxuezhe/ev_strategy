# 10 配置参数与运行指南

> 相关源码：`evtrade/cli.py`（backtest / sweep / replay 三个子命令）、常量（`evtrade/config.py`）。
> 本文档 2026-09-09 随统一 CPU/GPU 重构更新（删 `--engine`，统一 `--device`）；评分/选参方法论见 13 号文档。

## 1. 命令行结构

```
python -m evtrade backtest [参数]    # 单次回测 (= python mysql_analyze_demo.py)
python -m evtrade sweep    [参数]    # 参数并发扫描 + 鲁棒评分 (见 13 号文档)
python -m evtrade replay   [参数]    # 录制回放对账 (实盘一致性验收)
```

### backtest 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--period` | `5m` | K 线周期，**任意 数字+m/h/d**：5m/7m/90m/2h/4h/6h/1d/3d... |
| `--start` | `20250101` | 策略起始日期 YYYYMMDD（**之前 365 天自动作为预热**） |
| `--end` | `20260903` | 策略结束日期 YYYYMMDD |
| `--strategy` | `channel_deviation` | 策略 key（注册表名） |
| `--params` | (策略默认) | 策略参数 `k1:v1;k2:v2`（按 `params_spec` 校验） |
| `--device` | `auto` | **统一参数**：`cpu` (numpy) / `gpu` (cupy) / `auto` (gpu 可用则 gpu) |
| `--step-days` | 7 | 数据库分段查询步长（天，闭区间） |
| `--tf1` | 21 | 通道轨 EMA 周期（上轨 EMA(H,tf1)、下轨 EMA(L,tf1)） |
| `--no-sleep` | 关 | 去掉每根 bar 的 0.1s sleep；vectorized 引擎本就全速 |
| `--trade-qty` | 10000 | 每次信号交易股数（倍投时的基础数量） |
| `--scale` | 1.0 | 倍投系数：连续同向信号数量=上次×scale，反向重置（见 06 第 8 节） |
| `--code` | `159992.SZ` | 证券代码（示例：`159992.SZ` / `513120.SH`） |
| `--low1` | 1.5 | 下轨极端偏离阈值（%），置位 BUY 预备状态 |
| `--low2` | 1.0 | 下轨回撤确认阈值（%），触发 BUY。**必须 < low1** |
| `--high1` | 1.5 | 上轨极端偏离阈值（%） |
| `--high2` | 0.5 | 上轨回撤确认阈值（%）。**必须 < high1** |
| `--warmup-days` | 365 | 预热天数（拉取 start 之前的行情供指标就绪） |
| `--data-cache` | 无 | 行情 npz 缓存目录（命中后不访问数据库） |

> **2026-09-09 变化**: 删 `--engine {kernel, ref, vectorized}`。
> 旧 `--engine kernel` 自动映射为 `--device auto`，`--engine ref / vectorized` 自动映射为 `--device cpu`
> （仅打印 `DeprecationWarning`，不长期保留）。

代码内常量（不在命令行暴露）：`DB_URL`（环境变量 `EVTRADE_DB_URL` 可覆盖）、
`TABLE=minute_bars`、`INIT_CASH=200000`、`INIT_POSITION=200000股`、`TF1=21`。

### sweep 参数（评分语义见 13 文档）

`--grid "名字=v1,v2"`（可多次；支持 low1/low2/high1/high2/tf1/period/trade_qty/scale）、
`--splits d1,d2,d3`（滚动 WFO 窗）、`--split d`（单窗，兼容旧名）、`--fee-bp 5`、
`--score-lambda 1.0`、`--min-trades 30`、`--max-mdd`、`--mc 300`、`--mc-top 5`、
`--workers`、`--device cpu|gpu|auto`、`--synthetic-days N`（无库体验）、`--out`、`--top`。

> `--device` 在 sweep 中决定每组参数批量回测的后端 (cpu/gpu)。

### replay 参数

`--log`（bar 日志 CSV）、周期与策略参数同 backtest、`--warmup-until YYYYMMDHMMSS`、
`--against-ref`（同时用参考引擎回放并逐 bar 对账，输出 PASS/FAIL + 分歧统计）、
`--signals-out`（信号轨迹 CSV）。日志由 `evtrade.replay.append_bar / write_bars_log` 产生（实盘侧每根 bar 追加一行）。

> `--against-ref` 内部调 `evtrade.core.replay.reconcile`：
> vectorized vs Engine.on_bars 桶级信号 + 逐笔成交 bitwise 对账。
> 默认 `bucket_diff_cap=8`（lenient），`EVT_RECONCILE_STRICT=1` 时 cap=0（strict）。

## 2. 典型命令

```bash
# 安装依赖
pip install pymysql sqlalchemy pandas cupy-cuda12x  # cupy 可选

# 标准 CPU 全速回测
python -m evtrade backtest --strategy channel_deviation --device cpu \
    --period 5m --start 20250101 --end 20260903 --no-sleep

# GPU 回测（cupy 可用时自动 fallback 到 cpu）
python -m evtrade backtest --strategy channel_deviation --device gpu \
    --period 5m --start 20250101 --end 20260903 --no-sleep

# 小段快速验证参数
python -m evtrade backtest --strategy channel_deviation --params "tf1:21;low1:1.0" \
    --period 5m --start 20250601 --end 20250901 --no-sleep

# 换标的 + 1 小时周期 + 更苛刻的偏离阈值
python -m evtrade backtest --strategy channel_deviation --code 513120.SH \
    --period 1h --params "low1:2.0;low2:1.2;high1:2.0;high2:0.8" --no-sleep

# 带节奏的"仿真回放"（每根 1m bar 间隔 0.1s，观察实时行为）
python -m evtrade backtest --strategy channel_deviation --period 5m \
    --start 20250601 --end 20250615

# 回放对账
python -m evtrade replay --log /tmp/demo.log --strategy channel_deviation \
    --device cpu --against-ref
```

## 3. 运行前检查清单

1. 网络可达 `192.168.10.2:33066`，账号 `EvTrade` 可读 `evtrade` 库（凭据硬编码在 `cli.py`，属敏感信息）
2. `minute_bars` 表中存在目标 `stock_code`、且覆盖 `[start-365天, end]` 的数据
3. `stime` 列建议有索引（每段 SQL 都按 `stime` 范围 + 排序）
4. `low1 > low2`、`high1 > high2`（否则锁存失效）；参数经 `_resolve_params` 按 `params_spec` 校验
5. 数据量估算：1 年 1m ≈ 24 万根/标的（交易时段），乘以回测年数；首次运行留意磁盘与内存
6. GPU 路径需 `cupy` + `nvidia-*-cu12` pip 轮子；缺失时 `--device gpu` 自动回退到 cpu 并打 warning

## 4. 输出解读

### 4.1 分段进度（Feed 打印）

```
  -- 段 20240102~20240108 处理 8231 根, 累计 8231
```

每段（默认 7 天）打印一次；`累计` 是含预热在内的总 bar 数。长时间停在一段 = SQL 慢（查索引）。

### 4.2 信号行（Engine 打印，仅有信号时）

```
BUY  >>> [20250106101500] | UP=1.2345 DW=1.2340 | low_dev(L/DW)=2.31% high_dev(H/UP)=0.45%
        >> BUY  10000股 @ 1.2345  花费 12345.00  剩余资金 187655.00 持仓 210000
```

- 时间戳 = **桶 CLOSE 时的桶右端点 ts**（与 vectorized 路径同口径）。
- 数值按 4 位小数显示（`fmt` 函数）。
- 第二行是模拟成交明细（数量、金额、剩余资金、持仓）。

### 4.3 盈亏汇总

CLI 输出格式（与 vectorized / Engine 路径分别打印）：

**vectorized 路径**（16 字段）：
```
============ 回测盈亏汇总 (vectorized / cpu) ============
final_cash / final_position / final_equity
n_trades / n_buy / n_sell / turnover
cagr / sharpe / sharpe_excess / sortino / sortino_excess / calmar
max_dd_days / max_dd_recovered / max_drawdown
```

**Engine 路径**（6 项基础汇总）:
```
============ 回测盈亏汇总 (engine) ============
期末价 / 交易次数 / 期初资金·持仓 / 期末资金·持仓 / 期末持仓市值
策略总资产 / 不操作基线 / 盈亏差额(策略-基线) / 盈亏比例
```

- 盈亏为正 = 择时跑赢"拿着不动"；未扣手续费/滑点。
- 交易次数为 0 也正常（区间内没出现"极端偏离→回撤"完整过程）。
- vectorized 与 Engine 路径在相同样本上 `summary` 数值差异源自 equity_curve 累积 vs 不累积，n_trades / n_buy / n_sell 一致。

## 5. 性能建议

| 手段 | 效果 |
|---|---|
| `--device gpu` | GPU 路径用 cupy 算子；cupy 不可用时自动回退 cpu 并打 warning |
| `--no-sleep` | 去掉每根 0.1s 的人为延迟，回测提速主导项 |
| `--step-days` 调大（如 30） | 减少 SQL 往返次数；太小会拖慢、太大增内存 |
| 先 `--start/--end` 小区间调参 | 快速迭代阈值后再拉长区间 |
| 确认 `stime` 索引 | 分段范围查询是取数瓶颈所在 |

## 6. FAQ

**Q: 完全没有信号？**
先确认预热充分（`--period 1d` 且 start 前历史不足一年会导致指标就绪晚）；再观察偏离量分布——把 `--low1` 临时调小（如 0.5）看是否开始出信号，判断是阈值过严还是数据/代码问题。

**Q: 信号时间戳为什么是 10:15 而我以为是 10:10~10:14 的行情？**
桶 ts 是前开后闭区间的右端点，`[10:15]` 桶覆盖 `(10:10, 10:15]`。详见 04 文档。

**Q: 能回测多个标的吗？**
单次运行单标的（Feed 按 `stock_code` 过滤）。多标的需循环调用或自行扩展 Feed（见 11 文档）。

**Q: 如何改为实盘？**
换 Feed（`ChainedFeed(历史, 实时)`）+ 换 Executor（实现 `BrokerExecutor.trade` 接券商 API），Engine/策略/账户不动。见 07、11 文档。

**Q: 中途 Ctrl+C 会丢汇总吗？**
不会。`run()` 捕获 KeyboardInterrupt 后仍执行 `flush()`，`main` 继续走 `print_summary()`，基于已处理数据出汇总（未拉取的后续段自然缺失）。

**Q: GPU 与 CPU 结果对不上怎么办？**
通常发生在 cupy 不可用、auto 回退 cpu 时。显式传 `--device cpu` / `--device gpu` 排查；reconcile 的 `bucket_diff_cap` 默认容忍 EMA 累积漂移（≤8 桶），超出需检查指标实现或策略代码。

**Q: 旧脚本里的 `--engine kernel/ref/vectorized` 还能用吗？**
会打 `DeprecationWarning` 并自动映射（`kernel → auto`、`ref/vectorized → cpu`），下个版本会删除该兼容项。建议新脚本直接用 `--device`。
