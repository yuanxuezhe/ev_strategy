## 1. 统一策略契约

```python
class VectorizedStrategy:
    def init_state(self, params) -> state | None:
        return None                          # 无状态策略默认

    def step(self, state, bar, params) -> tuple[state, int]:
        raise NotImplementedError            # 子类必实现

    def format_signal_line(self, ts, sig, info=None) -> str:
        ...                                  # 展示 hook
```

**唯一抽象方法** = `step(state, bar, params) -> (state, sig)`。
`state` 由 engine 持有, 跨调用持续, 策略**无 instance attr**。
bar 契约: `{"ts","o","h","l","c","v","mark"}`(单桶)。
sig ∈ {-1, 0, 1}。`mark == 0`(预热)直接返 `(state, 0)`, framework 不做兜底。

子类实现 `step` 即可; stateful 策略覆写 `init_state` 返回 `@dataclass` 初值。

### 1.1 `params_spec` 与校验

```python
@register_strategy("my_strategy")
class MyStrategy(VectorizedStrategy):
    params_spec = {
        "p0": {"default": 21, "type": int, "min": 2, "max": 1000},
        "p1": {"default": 1.5, "type": float, "min": 0.0, "max": 100.0},
    }
```

校验逻辑由基类 `__init__` 自动完成(`_resolve_params`):

- 字段缺失用 default 填
- 类型不符抛 `ValueError`
- 超出 min/max 范围抛 `ValueError`
- 未声明的参数名抛 `ValueError`(防拼写错误)

### 1.2 `format_signal_line` 展示 hook

```python
def format_signal_line(self, ts, sig, info=None) -> str:
    ...
```

`ts / sig / info` 三参。hook 内**无 positional 指标**, 所需字段从 `info` dict 自取
(`info.get(...)`, 禁止 `info[k]` 下标, 防止 info 缺字段时 KeyError)。

约定(`openspec/changes/enrich-signal-line-context`):
策略 `step` 在 sig != 0 时 MUST 写 `self._last_info = {"side", "price", "o", "h", "l", "c", "v"}`,
hook 输出 MUST 含**方向词 (BUY/SELL) + 价格 + OHLCV**(`o=`/`h=`/`l=`/`c=`)。
锁定测试: `tests/test_format_signal_line_enrich.py`。
锁定 spec: `R: Strategy signal line shows trigger bar context`。

## 2. 策略自管执行(资金/持仓/撮合/账本)

> 2026-09-13 重构: framework 不再持有 `Account` / `Executor` / `SimulatedExecutor` /
> `trade_decision` / `metrics.summarize` 等业务概念。策略 `step` 内部自管。

每个策略的 `@dataclass` state 内含:

| 字段 | 含义 |
|---|---|
| `cash` / `position` | 当前现金 / 当前持仓股数 |
| `init_cash` / `init_position` | 期初快照(`init_state` 写入) |
| `trades` | 结构化成交 list `[{ts, side, qty, price}]` |

策略 `step` 内部当 sig != 0 时调内联撮合数学(与旧 `evtrade.execution.base.trade_decision` 等价):

```python
def _trade_decision(side, price, cash, position, cur_qty, buy_pct, sell_pct):
    if side > 0:
        max_by_cash = cash / price if price > 0 else 0.0
        if buy_pct > 0:
            q = min(buy_pct * max_by_cash, max_by_cash)
        else:
            q = min(cur_qty, max_by_cash)
        if q <= 0:
            return cash, position, 0.0, False
        return cash - q * price, position + q, q, True
    if sell_pct > 0:
        q = min(sell_pct * position, position)
    else:
        q = min(cur_qty, position)
    if q <= 0:
        return cash, position, 0.0, False
    return cash + q * price, position - q, q, True
```

**资金模式参数**(全部走 `--params`, CLI 无独立 flag):

| 参数 | 含义 | 默认 |
|---|---|---|
| `init_cash` | 期初资金 | 200000 |
| `init_position` | 期初持仓股数 | 0 |
| `trade_qty` | 每次信号交易股数 | 10000 |
| `buy_pct ∈ [0,1]` | BUY 时按当前 cash 的比例下注(0=关闭走 trade_qty) | 0.0 |
| `sell_pct ∈ [0,1]` | SELL 时按当前 position 的比例卖(0=关闭走 trade_qty) | 0.0 |

> CLI 不再有 `--init-cash --buy-pct --sell-pct --all-in --trade-qty` flag;
> 全部走 `--params`。framework **不**提供 `--fee-bp --min-trades --max-mdd --mc --mc-top`
> 等资金/绩效相关参数(由策略自管)。

## 3. `channel_deviation` —— 通道偏离回撤

### 3.1 策略思想

均值回归型策略, 使用 EMA 通道作为偏离参考。两段式判断:

- **第一段(极端偏离, 置位标记)**: 价格远跑到通道外 → 记下"发生过极端偏离"(锁存, 不动作)
- **第二段(回撤确认, 触发信号)**: 随后价格收回通道附近 → 触发买入/卖出

| 信号 | 含义 | 逻辑链 |
|---|---|---|
| **BUY** | 超跌反弹 | L 远低于下轨(`low_dev > low1`)→ 之后 H 回升到下轨上方/附近(`low_dev_h < low2`)→ 买 |
| **SELL** | 超涨回落 | H 远高于上轨(`high_dev > high1`)→ 之后 L 回落到上轨下方/附近(`high_dev_l < high2`)→ 卖 |

两段式 + 锁存 = **迟滞(hysteresis)**: 触发条件必须先"走出很远"再"收回来",
单边贴着阈值抖动不会连续打信号。

### 3.2 四个偏离量(全部为百分比)

| 变量 | 公式 | 直觉含义 | 用途 |
|---|---|---|---|
| `low_dev` | `(DW - L) / DW × 100` | L 低于下轨多少(>0 才在轨外) | 判定下轨**极端偏离** |
| `high_dev` | `(H - UP) / UP × 100` | H 高于上轨多少 | 判定上轨**极端偏离** |
| `low_dev_h` | `(DW - H) / DW × 100` | H 相对下轨的位置(H≥DW 时 ≤0) | BUY 触发: `< low2` 即 H 已收回到下轨上方或仅差一点 |
| `high_dev_l` | `(L - UP) / UP × 100` | L 相对上轨的位置(L≤UP 时 ≤0) | SELL 触发: `< high2` 即 L 已回落到上轨下方或仅差一点 |

> 方向注意: `low_dev_h < low2` 在 H 完全收回下轨上方时(负值)恒成立,
> 所以该条件表达的是"整根 bar 的最高点已回到下轨附近以内"。

### 3.3 默认参数

| 参数 | 默认 | CLI | 角色 |
|---|---|---|---|
| `tf1` | 21 | `--params "tf1:21"` | EMA 通道周期 |
| `low1` | 1.5% | `--params "low1:1.5"` | 下轨极端偏离阈值(置位) |
| `low2` | 1.0% | `--params "low2:1.0"` | 下轨回撤确认阈值(触发 BUY) |
| `high1` | 1.5% | `--params "high1:1.5"` | 上轨极端偏离阈值(置位) |
| `high2` | 0.5% | `--params "high2:0.5"` | 上轨回撤确认阈值(触发 SELL) |

**硬约束**: 必须 `low1 > low2`、`high1 > high2`, 否则"先冲出、再收回"的迟滞结构退化,
锁存失去意义。`validators` 跨字段校验锁定。

### 3.4 状态机与锁存

每个方向两个状态位 + 一个单桶操作锁:

```
low_hit=False ──low_dev>low1──▶ low_hit=True   (置位, 此后保持, 哪怕偏离回落)
low_hit=True  ──low_dev_h<low2──▶ BUY, low_hit=False  (触发并解除)
```

要点(见 `channel_deviation.py::_fsm_step`):

1. **置位后不会被清除**: 即使 low_dev 回落到 low1 以下, low_hit 仍是 True,
   必须等到回撤确认才触发并解除 —— 这就是"锁存"。
2. **触发基于"上一根遗留的标记"**: `_fsm_step` 先用进入时的 low_hit/high_hit 判断触发,
   再处理置位。
3. **单桶单操作**(`lock_ts / low_acted / high_acted`, 维护在 `state.fsm` dataclass):
   - 桶 ts 变化时(`cur_ts != lock_ts`)重置两个操作锁
   - 同一根周期桶内, 每个方向"置位"和"触发"合计**最多发生一次**(`not low_acted` 等守卫)
   - 目的: 防止桶内 H/L 大幅波动导致"置位→触发→再置位→再触发"的连环信号
4. **触发互斥**: BUY/SELL 判断是 `if / elif`, 同一桶最多出一个信号。

### 3.5 step 算法骨架

```python
@register_strategy("channel_deviation")
class ChannelDeviationStrategy(VectorizedStrategy):
    params_spec = {...}

    def init_state(self, params):
        st = ChannelDeviationState()
        st.init_cash = float(params["init_cash"])
        st.init_position = float(params["init_position"])
        st.cash = st.init_cash
        st.position = st.init_position
        return st

    def step(self, state, bar, params):
        if bar["mark"] == 0:
            return state, 0                          # 预热段

        tf1 = int(params["tf1"])
        # 1) EMA 通道 (stateful, 增量)
        if state.has_prev and state.prev_ts != int(bar["ts"]):
            state.ema, _, _ = ema_channel_step(state.ema, state.cur_high, state.cur_low, tf1)
        state.prev_ts = int(bar["ts"])
        state.cur_high = float(bar["h"]); state.cur_low = float(bar["l"])
        state.has_prev = True
        state.ema, up, dw = ema_channel_step(state.ema, bar["h"], bar["l"], tf1)
        if up == 0.0 or dw == 0.0:
            # 通道未就绪守卫
            state._last_info = {...}
            return state, 0

        # 2) 偏离 (stateless 算)
        devs = _compute_devs(up, dw, bar["h"], bar["l"])

        # 3) FSM (stateful, 锁存)
        sig = _fsm_step(state.fsm, int(bar["ts"]), devs,
                        float(params["low1"]), float(params["low2"]),
                        float(params["high1"]), float(params["high2"]))

        # 4) 自管撮合 (sig != 0)
        if sig != 0:
            new_cash, new_pos, q, filled = _trade_decision(
                sig, float(bar["c"]), state.cash, state.position,
                float(params["trade_qty"]),
                float(params["buy_pct"]), float(params["sell_pct"]))
            if filled:
                state.cash = new_cash
                state.position = new_pos
                state.trades.append({"ts": int(bar["ts"]),
                                     "side": "BUY" if sig > 0 else "SELL",
                                     "qty": q, "price": float(bar["c"])})

        # 5) 写 _last_info 给 format_signal_line hook
        state._last_info = {"side": "BUY"/"SELL"/"", "price": float(bar["c"]),
                            "o": float(bar["o"]), "h": float(bar["h"]),
                            "l": float(bar["l"]), "c": float(bar["c"]),
                            "v": float(bar["v"]), ...}
        return state, sig
```

### 3.6 不实现 `batched_step`

FSM 锁存(`lock_ts / low_hit / high_hit / low_acted / high_acted`)跨桶 latch 难 tensor 化;
sweep 走 ThreadPool 路径。

## 4. `ma_crossover` —— 双均线交叉(stateful + batched_step opt-in)

```python
@dataclass
class MACrossoverState:
    fast: EMAState
    slow: EMAState
    prev_diff: float = 0.0
    has_prev: bool = False

def step(self, state, bar, params):
    fast_p, slow_p = int(params["fast"]), int(params["slow"])
    close = float(bar["c"])

    state.fast, fast = ema_step(state.fast, close, fast_p)
    state.slow, slow = ema_step(state.slow, close, slow_p)

    if state.fast.count < fast_p:
        return state, 0                              # fast 未就绪

    diff = fast - slow
    sig = 0
    if state.has_prev:
        if diff > 0 and state.prev_diff <= 0: sig = 1
        elif diff < 0 and state.prev_diff >= 0: sig = -1
    state.prev_diff = diff
    state.has_prev = True
    return state, sig
```

`ma_crossover` 是纯 EMA 增量、无 FSM、可向量化, 因此**实现 `batched_step` 类方法 hook**:
sweep 在 `device != "cpu" + len(combos) ≥ 32 + gpu_available + 真覆写 hook` 时
走 `core/batched_sweep.py::run_batched` 一次出 `[N, T]` 信号。
详见 [07-PyTorch与性能 §batched_step hook](07-PyTorch与性能.md)。

## 5. `filtered_mr` —— 4 重过滤均值回归

`channel_deviation` 在单边暴涨暴跌中容易"接飞刀"。`filtered_mr` 叠加 **4 重过滤**:

| 过滤 | 作用 | 默认参数 |
|---|---|---|
| 大周期顺势 | 解决方向问题, 避免逆势 | `higher_period=1h` + EMA 60 |
| ADX 趋势强度 | 解决环境问题, 避开单边 | `ADX(14) > 30` 暂停 |
| ATR 波动率 | 规避暴涨暴跌 | `ATR(14) > 1.5 × ATR_MA(20)` 暂停 |
| Close 确认 FSM | 避免盘中影线刺穿即开仓 | 上一桶触轨 + 本桶 close 回到带内 |

### 5.1 大周期顺势过滤

策略维护**大周期桶跟踪**(用 `core/timeutils.bucket_ts_encoded` 判定桶切换,
不用 `BarAggregator` 因为它依赖 `Bar.stime` 而 step 只给 int ts):

- 当前 bar 的大周期桶 ts 变化 → finalize 旧桶(用旧桶 close 推进 `EMA(higher_ema_period)`)
- 大周期多头(`last_close > higher_ema`): 关闭上轨做空信号, 只允许下轨做多
- 大周期空头: 关闭下轨做多信号, 只允许上轨做空

### 5.2 ADX / ATR 增量计算(Wilder smoothing)

```
TR_t = max(H - L, |H - prev_close|, |L - prev_close|)
ATR_t = ATR_{t-1} + (TR_t - ATR_{t-1}) / atr_period
+DM_t = max(H - prev_close, 0) if (H - prev_close) > (prev_close - L) else 0
-DM_t = max(prev_close - L, 0) if (prev_close - L) > (H - prev_close) else 0
+DM_smooth_t = +DM_smooth_{t-1} + (+DM_t - +DM_smooth_{t-1}) / adx_period
-DM_smooth_t = -DM_smooth_{t-1} + (-DM_t - -DM_smooth_{t-1}) / adx_period
TR_smooth_t  = TR_smooth_{t-1} + (TR_t - TR_smooth_{t-1}) / adx_period
+DI = 100 × +DM_smooth / TR_smooth
-DI = 100 × -DM_smooth / TR_smooth
DX = 100 × |+DI - -DI| / (+DI + -DI)            (DI 和 = 0 时 DX = 0)
ADX_t = ADX_{t-1} + (DX_t - ADX_{t-1}) / adx_period
```

注意: 本实现用 `H - prev_close` / `prev_close - L`(与 ATR 共享 prev_close),
与教材 Wilder 标准的 `H - H_{t-1}` / `L_{t-1} - L` 在量级上接近但定义不同 ——
工程取舍(共用 prev_close 状态, 避免多存一份历史价)。
`ADX` 就绪需 `adx_count >= 2 * adx_period`(Wilder smoothing 标准)。

### 5.3 Close 确认 FSM

策略用 `state.touched_lower_prev` / `state.touched_upper_prev` 标记上一桶是否触轨。
**两桶连续触轨 + 本桶 close 回到带内 + 大周期顺势过滤** 才出信号:

```
touched_lower_prev=True AND 本桶 low < lower AND 本桶 close > lower AND higher_trend >= 0 → BUY
touched_upper_prev=True AND 本桶 high > upper AND 本桶 close < upper AND higher_trend <= 0 → SELL
```

- `higher_trend ∈ {-1, 0, +1}`: 大周期 `EMA(higher_ema_period)` 就绪后用末根 close 比较得出;
  EMA 未就绪时为 `0`, BUY/SELL 两侧条件均满足("未就绪 = 不挡")。
- 触轨 FSM 状态在策略 `step` 末尾更新(用本桶是否触轨覆盖 prev), 供下一桶判断。

### 5.4 决策矩阵

| 市场环境 | ADX | 大周期 | 动作 |
|---|---|---|---|
| 盘整震荡 | ≤ 30 | 任意 | 全功能(4 重过滤全过 → 出 close 确认信号) |
| 单边多头 | > 30 | 多 | 禁做空, 只允许低吸做多 |
| 单边空头 | > 30 | 空 | 禁做多, 只允许高抛做空 |
| 极端暴动 | 任意 | 任意 | ATR 异常放大 → 全停 |

### 5.5 params_spec

> 与 `channel_deviation` 不同: `filtered_mr` 在 `mark=0` 段仍累积 EMA/ATR/ADX 状态;
> `channel_deviation` 因为桶首/桶末 mark 在预热边界两侧不一致(vectorized 取首根、
> Engine 取末根), 整段跳过 EMA 累积以避免对账两侧 sig 漂移。

### 5.6 不实现 `batched_step`

大周期桶跟踪 + ADX Wilder 平滑 + FSM latch 三者混合下, torch 向量化收益小且语义易偏移,
按 spec "channel_deviation MUST NOT implement batched_step" 的精神保持 ThreadPool 路径。

## 6. 三策略汇总

| 策略 | 注册 key | 实现 `batched_step` | mark=0 累积 | 状态复杂度 |
|---|---|---|---|---|
| `channel_deviation` | `channel_deviation` | ❌ | ❌(整段跳过) | EMA + FSM + cash/position |
| `ma_crossover` | `ma_crossover` | ✅ | ✅ | EMA × 2 + cash/position |
| `filtered_mr` | `filtered_mr` | ❌ | ✅ | EMA × 2 + ATR/ADX + FSM + cash/position |
