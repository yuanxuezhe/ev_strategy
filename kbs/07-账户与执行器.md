# 07 账户与执行器

> 相关源码：`Account`（`evtrade/execution/account.py`）、`trade_decision` / `Executor` / `SimulatedExecutor`（`evtrade/execution/base.py`）

## 1. `Account` —— 资金/持仓记账（回测/实盘共用）

```python
Account(cash, position)
```

### 字段

| 字段 | 含义 |
|---|---|
| `init_cash` / `init_position` | 期初资金 / 期初持仓（快照，算基线用） |
| `cash` / `position` | 当前现金 / 当前持仓股数 |
| `trades` | 结构化成交流水 `list[dict]`：`{"ts", "side", "qty", "price"}` |

### 方法

**`apply(side, qty, price, ts)`** —— 纯记账，不含任何下单逻辑，由 Executor 在"确认成交"后调用：

- `BUY`：`cash -= qty*price`，`position += qty`
- `SELL`：`cash += qty*price`，`position -= qty`
- 追加一条结构化成交记录到 `self.trades`

注意：不校验资金/持仓是否足够（前置检查在 Executor 的 `trade_decision` 里做）；`Account` 本身不考虑手续费/滑点/印花税——如需建模，在 Executor 层（`apply` 之前）扣减 cash 后再调 `apply`（当前回测模型为理想化成交）。`Account` 只做记账，**无权益估值方法**（`equity` / `baseline_equity` 已于 2026-09-10 prune-dead-equity-api 删除）——权益/基线由 `metrics.summarize` 从 `final_state` 实算（见 09 文档）。

## 2. `Executor` —— 下单抽象

```python
class Executor:
    def trade(self, signal: str, price: float, ts: str) -> bool: raise NotImplementedError
```

策略/引擎只调 `executor.trade(signal, price, ts)`，不关心背后是模拟还是真实委托。返回 bool 表示是否成交。`Executor` 基类只有 `trade` 一个抽象方法（`update_price` 钩子已于 2026-09-10 prune-dead-equity-api 删除——唯一消费者 Account 估值方法不存在，`trade` 自带价格）。

### 2.1 `SimulatedExecutor`（回测用）

```python
SimulatedExecutor(account, qty, verbose=True, scale=1.0,
                  buy_pct=0.0, sell_pct=0.0, all_in=False, record_to=None)
```

- **成交价**：信号当根的最新 close（Engine 传入的 `price = cur["close"]`）
- 取量逻辑统一走 `trade_decision`（见下节 3），成交后调 `account.apply(...)`；verbose 模式打印带剩余资金/持仓的成交行
- `record_to`（可选 list）：每次成功成交追加 `{ts, side, qty, price}` 副本（replay/对账用）

**scale（倍投）**：同方向连续信号时，下一笔数量 = 上一笔 × scale（首笔为 `qty`）；方向翻转时重置为基础数量 `qty`。信号即计数（未成交也计）；`1.0` = 关闭。
**注意**：`scale` / `last_side` 是**调用方（executor）侧状态**，executor 自己维护并算好 `cur_qty` 后再传给 `trade_decision`——`trade_decision` 本身无状态。

**资金模式**：

| 参数 | 含义 |
|---|---|
| `buy_pct ∈ [0,1]` | BUY 时按当前 `cash` 的比例下注 |
| `sell_pct ∈ [0,1]` | SELL 时按当前 `position` 的比例卖 |
| `all_in=True` | 等价于 `buy_pct=sell_pct=1.0` |
| 三者均为 0 | 走 fixed-qty 路径（按 `cur_qty`） |

### 2.2 实盘执行器（自定义 `Executor` 子类）

仓库内**不存在**占位的实盘执行器（旧版实盘占位实现已删除，无对应类）。接入真实交易 = 自己写一个 `Executor` 子类：

```python
class MyLiveExecutor(Executor):
    def trade(self, signal, price, ts) -> bool:
        order_id = self.broker.place_order(signal, ...)   # 向券商下单
        # 成交回报到达后:
        self.account.apply(signal, actual_qty, actual_price, ts)   # 用真实成交价记账
        return True
```

接入实盘时的要点：

1. 真实成交是**回报驱动**的：`trade()` 返回 True 的时机应是**成交回报**到达时；期间持仓/资金以券商侧为准
2. 记账时机 = 成交回报，价格 = 实际成交均价（而非信号价），数量 = 实际成交数量；调 `account.apply(side, actual_qty, actual_price, ts)` 完成记账
3. 需处理拒单/部分成交/撤单等分支：部分成交时 `apply` 只接收已成交的部分；拒单/撤单则 `trade` 返回 False 且不调 `apply`
4. 手续费/滑点在 Executor 层（`apply` 之前）扣减 cash，不进 `Account`

## 3. `trade_decision` —— 单一成交决策（两条引擎路径共用）

模块级函数（`evtrade/execution/base.py`）：

```python
trade_decision(side, price, cash, position, cur_qty, buy_pct, sell_pct)
    -> (new_cash, new_position, qty, filled)
```

这是**唯一的取量 + 资金/持仓约束 + 现金持仓更新**实现，`SimulatedExecutor.trade` 与 vectorized 引擎的 `_execute_trades` **共用同一份**，保证两条路径逐笔成交 bitwise 一致——这正是 `replay --against-ref` 对账所检查的成交口径。

参数：

- `side`：`1=BUY`、`-1=SELL`（调用方保证非 0）
- `cur_qty`：本轮基础数量（scale 倍投后的量，由调用方维护）
- `buy_pct` / `sell_pct`：见 2.1 资金模式

**BUY（`side > 0`）**：

```
price > 0:
    max_by_cash = cash / price
    if buy_pct > 0: q = min(buy_pct * max_by_cash, max_by_cash)   # 按现金比例
    else:           q = min(cur_qty, max_by_cash)                 # fixed-qty
price == 0: q = 0
```

**SELL（`side < 0`）**：

```
if sell_pct > 0: q = min(sell_pct * position, position)   # 按持仓比例
else:            q = min(cur_qty, position)               # fixed-qty
```

**成交判定**：

- `q <= 0`（没钱/没票/价格为 0）→ 不成交，返回 `(cash, position, 0.0, False)`——`filled=False` 时**现金/持仓原样返回**（不做任何更新）
- 否则 BUY：`(cash - q*price, position + q, q, True)`；SELL：`(cash + q*price, position - q, q, True)`

## 4. 数量与资金约定

| 项 | 默认值 | 说明 |
|---|---|---|
| INIT_CASH | 200000.0 | 期初资金 20 万（`config.INIT_CASH`） |
| INIT_POSITION | 200000.0 | 期初持仓 **20 万股**（`config.INIT_POSITION`）——有底仓，SELL 信号才有票可卖 |
| TRADE_QTY | 10000.0 | 每次信号交易 1 万股（`--trade-qty` 可调） |

这个配置意味着：策略是"在 20 万股底仓上做 1 万股级别的择时加减仓"，基线 = 20 万现金 + 20 万股按期末价的市值。

## 5. 账务口径小结

- 权益 = 现金 + 持仓 × 最新价（期末价由 `metrics.summarize` 的 `final_state.last_price` 提供，vectorized 引擎自维护，不经 `Account`）
- 盈亏口径 = 策略期末总资产 − 不操作基线（同一期末价估值，消除行情涨跌的影响，只留择时贡献）
- 无手续费/滑点模型（在 Executor 层外建模）；对比实盘结果时应预期回测偏乐观
