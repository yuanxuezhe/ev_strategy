# 01 总览

> **项目定位** + **架构总览** + **核心特性** + **包结构**
>
> 2026-09-13 后:framework 不再持有资金/持仓/撮合/PnL/收益概念;
> 业务概念下放到策略 `step` 内部 + `@dataclass state` 字段 + 策略内联撮合数学。
> framework 只做 (1) 桶预计算 + (2) `step` 驱动循环 + (3) 可选 GPU-batched sweep hook。
> CPU/GPU 双端统一由 PyTorch 后端提供 (`backends.get_xp`)。

## 1. 项目定位

**回测 + 实盘统一架构**的量化交易演示框架:

- **数据**: MySQL `evtrade.minute_bars` 表(1m 原始行情); 任意 `m/h/d` 周期合并
- **核心能力**: EMA 通道偏离策略(`channel_deviation` / `ma_crossover` / `filtered_mr`)
- **目标**: 同一套引擎代码, 回测跑历史 / 实盘接实时, 只换"行情源"组件

## 2. 分层架构

```
数据层      MySQL minute_bars ──┐
                                │ load_bars / synthetic_bars (core/data.py)
                                │ 单次全量 + npz 缓存
                                ▼
bar 流层    ListBarFeed ─── yield Bar ───▶ (任意 .stream() -> Iterator[Bar])
                                │
                                ▼
合并层      BarAggregator     1m → 目标周期桶; 桶切换时调 on_bars
                                │
                                ▼
引擎层      Engine.on_bars /  桶 CLOSE 语义 (上一桶 finalized OHLCV)
            run_vectorized    调 strategy.step(state, bar, params)
                                │
                                ▼
策略层      VectorizedStrategy  ├─ ema_channel_step (策略 step 内增量)
                                ├─ 偏离 + 锁存 FSM (Python 循环)
                                └─ step(state, bar) 单方法
                                │
                                ▼
展示层      format_signal_line  信号行打印 hook (无 positional 指标)
```

framework **不假定任何指标字段名**; EMA / FSM 等都是策略私有 state,
由 `step` 内部维护。**切换回测/实盘 = 换 bar 流**; 策略撮合/账本由
`step` 内部自管 (无 Executor / Account 介入)。

## 3. 核心特性

| # | 特性 | 说明 |
|---|---|---|
| 1 | 纯增量计算 | 周期合并 O(1)/根, EMA 通道 O(1)/桶 (`ema_channel_step`) |
| 2 | 前开后闭桶 | 桶 ts 标注右端点 (与通达信等主流软件一致) |
| 3 | 预热机制 | 默认 365 天预热 (`mark=0`), 策略期才驱动 (`mark=1`) |
| 4 | 锁存式策略 | 极端偏离置位 → 回撤确认触发, 天然迟滞 |
| 5 | 单桶单操作 | 同桶内每个方向最多一次状态转换 |
| 6 | 组件解耦 | bar 流 / 合并器 / 策略 / 指标 / 撮合数学 各自独立可替换 |
| 7 | 单一策略契约 | `step(state, bar, params) -> (state, sig)`; vectorized / 逐 bar 走同一份 |

## 4. 技术栈

| 项 | 说明 |
|---|---|
| 语言 | Python 3.10+ (`from __future__` + dataclass + PEP 604 联合类型) |
| 数据库 | `pymysql` + `sqlalchemy` (`create_engine`, `pool_pre_ping=True`, `pool_recycle=3600`) |
| 数值/向量化 | `numpy` (合成数据 + 批量参考) |
| 数据处理 | `pandas` (`pd.read_sql` 在 `core/data._fetch` 延迟 import) |
| 深度学习/后端 | `torch>=2.0` (CPU/GPU 统一后端; 默认 CPU wheel, GPU 由 `scripts/sync-torch-cu.sh` 覆盖到 cu128) |

## 5. 关键默认值(速查)

```
数据库        192.168.10.2:33066/evtrade (EVTRADE_DB_URL 可覆盖)
数据表        minute_bars           (EVTRADE_TABLE 可覆盖)
K 线周期      5m (--period 任意 m/h/d)
策略区间      20250101 ~ 20260903
证券          159992.SZ
设备          auto (--device cpu|gpu|auto)
策略          channel_deviation (默认)
预热天数      365 天 (load_bars.warmup_days)
```

> 策略私有参数(`tf1` / `low1/low2/high1/high2` / `init_cash` / `trade_qty` 等)
> 全部走 `--params "k1:v1;k2:v2"`, 按 `params_spec` 校验。落盘默认参数在
> `evtrade/strategies/_defaults/<strategy>.json`。

## 6. 快速上手

```bash
# CPU 标准回测
python -m evtrade backtest --strategy channel_deviation \
    --period 5m --start 20250101 --end 20260903 --device cpu

# 换标的 + 1h 周期 + 更苛刻偏离阈值
python -m evtrade backtest --strategy channel_deviation --code 513120.SH \
    --period 1h --params "low1:2.0;low2:1.2;high1:2.0;high2:0.8"

# 合成数据 (无库体验)
python -m evtrade backtest --strategy channel_deviation \
    --synthetic-days 120 --period 5m --start 20260101 --end 20260201

# 网格扫描 + 鲁棒评分
python -m evtrade sweep --strategy channel_deviation --device auto \
    --grid "low1=1.2,1.5,2.5" --grid "low2=0.5,1.0,1.5" \
    --splits 20250901 20260301 --out results.csv
```

```
├── scripts/                        # run.bat / sync-torch-cu.sh
├── README.md / CLAUDE.md
└── pyproject.toml / uv.lock
```
