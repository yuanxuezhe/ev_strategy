# 11 扩展指南

> 设计意图（文件头 `mysql_analyze_demo.py:16`）：**切换实盘/回测：换 Feed + 换 Executor，其余不变。**
> 本文给出各扩展点的具体做法与注意事项。

## 1. 新增行情源（Feed）

继承 `Feed`，实现 `stream()`：

```python
class LiveFeed(Feed):
    def __init__(self, code: str): ...
    def stream(self) -> Iterator[Bar]:
        while True:
            tick = ...                      # 从行情 API / websocket 取数
            yield Bar(stime=..., code=self.code, open=..., high=...,
                      low=..., close=..., volume=...)
```

必须遵守的契约：

1. `stime` 为 14 位 `YYYYMMDDHHmmss` 字符串（预热比较、SQL、排序全依赖字符串序）
2. 从旧到新、单调不减（桶合并按顺序推进，乱序会污染 open/close 与桶切换）
3. 字段类型与 `Bar` 一致（volume 为 int）

实盘组合用 `ChainedFeed`：先历史预热（mark=0 累积指标）再接实时：

```python
feed = ChainedFeed(MySQLBacktestFeed(code, start, today, warmup_days=365), LiveFeed(code))
```

实时源额外注意：断线重连后从最后 stime 续传、去重（同 stime 重复推送会被当成同桶更新，volume 会重复累加）、收盘后无数据时的阻塞策略。

## 2. 新增执行器（Executor）

继承 `Executor`，实现 `trade(signal, price, ts) -> bool`：

- 回测类：自行决定撮合模型（当前 `SimulatedExecutor` 是"当根最新 close 即时全额成交、买满/卖完"）
- 实盘类（`BrokerExecutor` 现为占位）：`place_order` 提单 → 等成交回报 → **回报到达后**调 `account.apply(side, 实际成交量, 实际成交均价, ts)`
- 资金/持仓可行性检查在 trade 内完成（`Account.apply` 不做校验）
- 若引入手续费/滑点：在 `apply` 外层额外扣减 `cash`，并同步调整 `print_summary` 口径

## 3. 新增/修改策略

**推荐路径 (2026-09-06 起)**: 把策略主逻辑写成 DSL (compute_signal docstring),
三端 (Python 参考引擎 / numba 内核 / CUDA 内核) 自动可用 —— 三步法与 DSL 白名单、
ctx 字段契约见 **14 号文档** (最小完整示例: `strategies/example_dev_trigger.py`)。

不走 DSL 的兜底路径 (仅参考引擎, 慢约 500x): 策略只需满足接口
`check(cur: dict, up, dw) -> (signal|None, info)`。

- `cur` 是当前周期桶 dict（键见 03 文档），`up/dw` 为通道值（可能为 None）
- 返回 `signal ∈ {"BUY","SELL",None}`；Engine 会以 `cur["close"]` 调 `executor.trade`
- 建议保留 `info` dict 作为打印/复盘载体（Engine 的信号行直接消费它）

改造现有策略时注意三个既有机制别丢掉：

1. **锁存（hysteresis）**：置位与触发分离，`low1 > low2`、`high1 > high2`
2. **单桶单操作**：`_bucket_ts/_low_acted/_high_acted`，防桶内反复触发
3. **None 防御**：`up/dw` 为 None 或 0 直接返回，不产生信号

## 4. 周期（2026-09-05 起支持任意 m/h/d）

**无需改代码**：`--period 90m` / `--grid "period=30m,2h,6h"` 直接可用（桶算法已升级为
本地锚定 epoch 取整，见 04 第 5 节）。要点：

- 格式 `数字+m/h/d`，如 7m/45m/90m/2h/6h/3d/7d（`resolve_period_seconds` 校验）；
- 能整除天长的周期边界对齐钟面（如 2h/6h），否则边界相对钟面每日漂移（如 7m），
  分区始终连续无重叠；
- 周期越大，验证窗内桶数/成交越少（`--min-trades` 会自然过滤），同时确认
  `--warmup-days` 足够 EMA seed（tf1 个桶）；
- `PERIODS` 预设表现在只是 CLI 默认值与文档示例，不再是周期白名单。

## 5. 调整通道指标

- 改参数：`--tf1`；上/下轨分别对 H/L 做 EMA 的结构在 `EMAChannel`
- 换指标（如布林带）：实现同接口 `push(high, low)`（桶闭合）+ `channel(cur_h, cur_l) -> (up, dw|None)`，替换 `Engine.ema_ch` 即可；`_sync_ema` 的游标机制可原样复用
- 校验方法：用纯函数版思路写批量重算，对比增量输出（项目内 `ema`/`ema_channel` 与 `IncrementalEMA`/`EMAChannel` 就是这种互验关系）

## 6. 其他常见改造点

| 需求 | 改哪里 |
|---|---|
| 多标的回测 | 外层循环 `--code`；或在 Feed 内去过滤并给桶加 code 维度（Aggregator 目前是单标的单实例） |
| 手续费/滑点 | `SimulatedExecutor.trade` 成交价加滑点；`Account.apply` 扣费用；`print_summary` 保持"总资产"口径自动体现 |
| 止损/止盈 | 在 `Engine.on_bars` 里 signal 判定后追加风控检查（拿得到 cur 的 H/L/C 与账户持仓） |
| 输出到文件/数据库 | 替换 `SimulatedExecutor`/`Engine` 中的 `print`；`account.trades` 已是结构化流水 |
| 持仓过夜/周末 gap | 当前模型无处理（信号即成交）；实盘接入时在 BrokerExecutor 层考虑集合竞价与涨跌停 |
| 数据库配置外置 | `DB_URL` 改为环境变量/配置文件（当前硬编码，含密码，注意不要提交到公开仓库） |
