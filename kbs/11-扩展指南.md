# 11 扩展指南

> 设计意图（`evtrade/core/engine.py` 文件头）：
> **切换实盘/回测：换 Feed + 换 Executor，其余不变。**
> 本文给出各扩展点的具体做法与注意事项。
> 本文档为 2026-09-09 统一 CPU/GPU 重构版（DSL 已废，全部 Python + xp）。

## 1. 新增行情源（Feed）

继承 `Feed`，实现 `stream()`：

```python
class LiveFeed(Feed):
    def __init__(self, code: str): ...
    def stream(self) -> Iterator[Bar]:
        while True:
            tick = ...                      # 从行情 API / websocket 取数
            yield Bar(stime=..., code=self.code, open=..., high=...,
                      low=..., close=..., volume=...)
```

必须遵守的契约：

1. `stime` 为 14 位 `YYYYMMDDHHmmss` 字符串（预热比较、SQL、排序全依赖字符串序）
2. 从旧到新、单调不减（桶合并按顺序推进，乱序会污染 open/close 与桶切换）
3. 字段类型与 `Bar` 一致（volume 为 int）

实盘组合用 `ChainedFeed`：先历史预热（mark=0 让策略累积自己的指标状态）再接实时：

```python
feed = ChainedFeed(MySQLBacktestFeed(code, start, today, warmup_days=365), LiveFeed(code))
```

实时源额外注意：断线重连后从最后 stime 续传、去重（同 stime 重复推送会被当成同桶更新，volume 会重复累加）、收盘后无数据时的阻塞策略。

## 2. 新增执行器（Executor）

继承 `Executor`，实现 `trade(signal, price, ts) -> bool`：

- 回测类：自行决定撮合模型（当前 `SimulatedExecutor` 是"当根最新 close 即时全额成交、买满/卖完"）
- 实盘类（`BrokerExecutor` 现为占位）：`place_order` 提单 → 等成交回报 → **回报到达后**调 `account.apply(side, 实际成交量, 实际成交均价, ts)`
- 资金/持仓可行性检查在 trade 内完成（`Account.apply` 不做校验）
- 若引入手续费/滑点：在 `apply` 外层额外扣减 `cash`，并同步调整 `print_summary` 口径

## 3. 新增/修改策略

**唯一契约**: 继承 `VectorizedStrategy`（`evtrade/strategies/vectorized_base.py`），
覆写 `compute_signals(self, xp, bars, params) -> xp.ndarray[int8]` 即可。

```python
from evtrade.strategies.vectorized_base import (
    VectorizedStrategy, register_strategy,
)
from evtrade.indicators import xp_ema, xp_ema_channel

@register_strategy("my_strategy")
class MyStrategy(VectorizedStrategy):
    params_spec = {
        "p0": {"default": 21, "type": int, "min": 2, "max": 1000},
        "p1": {"default": 1.5, "type": float, "min": 0.0, "max": 100.0},
    }

    def compute_signals(self, xp, bars, params):
        p0 = int(params["p0"])
        up, dw = xp_ema_channel(xp, bars["h"], bars["l"], p0)
        # ... 算 signal, 返 xp.ndarray[int8] ...
        return sig
```

- `xp` 是 numpy 或 cupy 模块（**不要**直接 `import numpy / cupy`，全部走 `xp` 抽象）
- `bars` 契约: `{"ts", "o", "h", "l", "c", "v", "mark", "n_bars"}`（全部 1D 数组）
- 返回数组长度 == `len(bars["ts"])`，元素 ∈ {-1, 0, 1}
- `mark == 0` 桶建议输出 0；framework 内部再做 `sig *= mark` 兜底

**需要逐 bar 路径维护 instance state 时**（如 channel_deviation 的桶切换增量 EMA + FSM），
覆写 `compute_signals_for_one_bar(self, xp, bar, params) -> int`：

```python
def compute_signals_for_one_bar(self, xp, bar, params):
    # self._up_st / self._dw_st 在 __init__ 初始化
    # 桶切换时调 ema_push 把上一桶 finalized high/low 入 EMA
    # 当前通道值用 ema_current 算
    # 调 _fsm_step(state, ...) 返回 0/1/-1
    ...
```

**共享状态机 + helper**: 批量路径与逐 bar 路径**共享**模块级 helper
（`_parse_thresholds` / `_compute_devs_scalar` / `_compute_devs_xp` / `_run_fsm`），
特别是 `_run_fsm` 强制两处调用 `_fsm_step` 的传参顺序一致。
`channel_deviation.py` 是范式 —— 见 `kbs/06-交易策略详解.md §5`。
`reconcile` 测试锁定两个入口 bitwise 一致。

**何时抽 helper**:
- 同一公式在两个方法体里出现 ≥2 次（参数解析、4 偏离、FSM 调用形态）
- helper 是 `_` 前缀 module-level 函数，不属于 framework 公共契约
- 单策略单文件 1 套 helper 即可；多策略共享再考虑抽到 `strategies/_common.py`（本项目尚未触发）

`params_spec` 校验逻辑由基类 `__init__` 自动完成（`_resolve_params`）：
- 字段缺失用 default 填
- 类型不符抛 ValueError
- 超出 min/max 范围抛 ValueError
- 未声明的参数名抛 ValueError（防拼写错误）

### 改造现有策略时注意三个既有机制别丢掉

1. **锁存（hysteresis）**：置位与触发分离，`low1 > low2`、`high1 > high2`
2. **单桶单操作**：维护在 instance `_fsm` dict（`lock_ts / low_acted / high_acted`），
   防桶内反复触发
3. **指标未就绪防御**：`ema_current` 未就绪时返回 `0.0`，策略代码 `if up == 0.0 or dw == 0.0: return 0` 守卫；
   批量路径由 `_compute_devs_xp` 内部 `ready mask` 自动短路。

## 4. 周期（任意 m/h/d）

**无需改代码**：`--period 90m` / `--grid "period=30m,2h,6h"` 直接可用（桶算法已升级为
本地锚定 epoch 取整，见 04 第 5 节）。要点：

- 格式 `数字+m/h/d`，如 7m/45m/90m/2h/6h/3d/7d（`resolve_period_seconds` 校验）；
- 能整除天长的周期边界对齐钟面（如 2h/6h），否则边界相对钟面每日漂移（如 7m），
  分区始终连续无重叠；
- 周期越大，验证窗内桶数/成交越少（`--min-trades` 会自然过滤），同时确认
  `--warmup-days` 足够让策略自己的指标完成 seed（如 EMA 需 tf1 个桶）；
- `PERIODS` 预设表现在只是 CLI 默认值与文档示例，不再是周期白名单。

## 5. 调整/新增指标（纯 Python + xp）

**新增指标**（如布林带 / ATR / RSI / 自定义动量）只需在 `evtrade/indicators/<name>.py` 加函数，
**framework 0 改动**：

1. **批量 xp 版**: `xp_<name>(xp, values, ...)` —— `compute_signals` 主体使用。
2. **增量 Python 版**: `<name>_push(state, value, ...) -> state` + `<name>_current(state, pending, ...) -> value`
   —— `compute_signals_for_one_bar` 覆写时使用。

示例（布林带增量版）:

```python
# evtrade/indicators/boll.py
def boll_push(mid_st, up_st, dw_st, value, p, k):
    # ... 同 EMA 思路的 SMA seed + 递推 ...
    return new_mid_st, new_up_st, new_dw_st

def boll_current(mid_st, up_st, dw_st, value, p, k):
    # ... 返回 (mid, upper, lower)
    return mid, upper, lower

# 策略 compute_signals 中使用:
mid, upper, lower = boll_current(self._mid_st, self._up_st, self._dw_st,
                                  cur_close, int(params["tf1"]), float(params["k"]))
```

**调整已有指标**（如改 EMA 默认周期）：改策略 `params_spec` 里 `tf1` 默认值，无需改 framework。

> **历史警示已撤销**: 旧版"换指标需同步改内核 step + CUDA 模板"在 `change 2026-09-09-decouple-indicators-from-framework`
> + `change 2026-09-09-unify-strategy-contract` 后**完全作废**——kernel step 与 CUDA 模板已删除（无 numba / 无 CUDA）；
> 指标完全由策略 `compute_signals` / `compute_signals_for_one_bar` 内部调 `evtrade.indicators/` 维护。

- 校验方法：用纯函数版思路写批量重算，对比增量输出（项目内 `indicators/ema.py` 同时保留 `xp_ema` 批量版与 `ema_push/ema_current` 增量版，互为校验）。

## 6. 其他常见改造点

| 需求 | 改哪里 |
|---|---|
| 多标的回测 | 外层循环 `--code`；或在 Feed 内去过滤并给桶加 code 维度（Aggregator 目前是单标的单实例） |
| 手续费/滑点 | `SimulatedExecutor.trade` 成交价加滑点；`Account.apply` 扣费用；`print_summary` 保持"总资产"口径自动体现 |
| 止损/止盈 | 在 `Engine.on_bars` 里 signal 判定后追加风控检查（拿得到 cur 的 H/L/C 与账户持仓） |
| 输出到文件/数据库 | 替换 `SimulatedExecutor`/`Engine` 中的 `print`；`account.trades` 已是结构化流水 |
| 持仓过夜/周末 gap | 当前模型无处理（信号即成交）；实盘接入时在 BrokerExecutor 层考虑集合竞价与涨跌停 |
| 数据库配置外置 | `DB_URL` 改为环境变量/配置文件（当前硬编码，含密码，注意不要提交到公开仓库） |

## 7. 策略展示 hook (2026-09-08 框架去特殊化; 2026-09-09 简化)

框架层**不假定任何指标字段名**; 信号行打印由策略覆写 `format_signal_line` 完成
（`VectorizedStrategy` 默认实现仅打 OHLCV + 信号；`ChannelDeviationStrategy` 实现于 `channel_deviation.py::format_signal_line`）。

| Hook | 签名 | 用途 | 默认实现 |
|---|---|---|---|
| `format_signal_line` | `(ts, sig, info) -> str` | verbose 引擎的信号行打印；**无 positional 指标**，所需字段从 `info` dict 自取 | 仅打 OHLCV + 信号 |

> **2026-09-09 变化**: 删除 `get_extra_bucket_columns` / `get_extra_signal_columns`（旧 bucket_table / per-bar bundle）。
> framework 输出列已简化为 OHLCV + sig（桶表） / `(stime, signal)`（信号轨迹）；
> 策略若需要展示列, 应在 `format_signal_line` 内一次性算（verbose 引擎才打）。
