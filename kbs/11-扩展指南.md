# 11 扩展指南

> 设计意图（`evtrade/core/engine.py` 文件头）：
> **切换实盘/回测：换 bar 流 + 换 Executor，其余不变。**
> 本文给出各扩展点的具体做法与注意事项。
> 本文档为 2026-09-09 统一 CPU/GPU 重构版（DSL 已废，全部 Python + xp）。

## 1. 新增行情源（bar 流）

bar 流是**鸭子类型**对象：只需提供 `.stream() -> Iterator[Bar]` 方法，无需继承基类。

```python
class LiveStream:
    def __init__(self, code: str): ...
    def stream(self) -> Iterator[Bar]:
        while True:
            tick = ...                      # 从行情 API / websocket 取数
            yield Bar(stime=..., code=self.code, open=..., high=...,
                      low=..., close=..., volume=...)
```

必须遵守的契约：

1. `stime` 为 14 位 `YYYYMMDDHHmmss` 字符串（预热比较、SQL、排序全依赖字符串序）
2. 从旧到新、单调不减（桶合并按顺序推进，乱序会污染 open/close 与桶切换）
3. 字段类型与 `Bar` 一致（volume 为 int）

实盘组合用"自定义组合 bar 流"：先历史预热（mark=0 让策略累积自己的指标状态）再接实时：

```python
# 自定义组合 bar 流: 先迭代历史 (预热), 再迭代实时
class HistThenLive:
    def stream(self):
        yield from load_history_bars(code, start, today, warmup_days=365)  # 历史预热
        yield from live(code)                                              # 接实时
```

实时源额外注意：断线重连后从最后 stime 续传、去重（同 stime 重复推送会被当成同桶更新，volume 会重复累加）、收盘后无数据时的阻塞策略。

## 2. 新增执行器（Executor）

继承 `Executor`，实现 `trade(signal, price, ts) -> bool`：

- 回测类：自行决定撮合模型（当前 `SimulatedExecutor` 是"当根最新 close 即时全额成交、买满/卖完"，成交决策收口 `trade_decision`，与 vectorized 引擎共用保证逐笔 bitwise 一致）
- 实盘类（自定义 `Executor` 子类）：`place_order` 提单 → 等成交回报 → **回报到达后**调 `account.apply(side, 实际成交量, 实际成交均价, ts)`
- 资金/持仓可行性检查在 trade 内完成（`Account.apply` 不做校验）
- 若引入手续费/滑点：在 `apply` 外层额外扣减 `cash`，并同步调整 `metrics.summarize` 口径

## 3. 新增/修改策略 (strategy-step-only, 2026-09-10)

**唯一契约**: 继承 `VectorizedStrategy`（`evtrade/strategies/vectorized_base.py`），
实现 `step(self, state, bar, params) -> (state, int)` 一个方法。
无状态策略覆写 `init_state(self, params) -> None`；stateful 策略覆写返 `@dataclass`。

```python
from dataclasses import dataclass
from evtrade.strategies.vectorized_base import (
    VectorizedStrategy, register_strategy,
)
from evtrade.indicators import EMAState, ema_step

@dataclass
class MyState:
    ema: EMAState = None  # dataclass field

@register_strategy("my_strategy")
class MyStrategy(VectorizedStrategy):
    params_spec = {
        "p0": {"default": 21, "type": int, "min": 2, "max": 1000},
        "p1": {"default": 1.5, "type": float, "min": 0.0, "max": 100.0},
    }

    def init_state(self, params):
        return MyState(ema=EMAState())

    def step(self, state, bar, params):
        if bar["mark"] == 0:
            return state, 0
        p0 = int(params["p0"])
        state.ema, ema = ema_step(state.ema, float(bar["c"]), p0)
        # ... 算 sig, 返 (state, sig) ...
        return state, sig
```

- `state` 是上一调用返回的 state，跨调用由 **engine 持有** (策略无 instance attr)
- `bar` 契约: `{"ts", "o", "h", "l", "c", "v", "mark"}` (单桶)
- 返回元组 `(state, sig)`, sig ∈ {-1, 0, 1}
- `mark == 0` (预热) 直接返 `(state, 0)`; framework 不做兜底

**engine 循环调 step**: `VectorizedEngine._compute_signals` 与 `Engine.on_bars`
都循环调 `strategy.step(state, bar, params)`, state 由 engine 持有 (dataclass 实例)。
两条路径走同一份 step 算法, 信号 bitwise 一致 (reconcile 测试锁定)。

**`channel_deviation.py` 是范式** —— 单 step 方法 (~15 行) + `ChannelDeviationState` dataclass,
详见 `kbs/06-交易策略详解.md §5`。

`params_spec` 校验逻辑由基类 `__init__` 自动完成（`_resolve_params`）：
- 字段缺失用 default 填
- 类型不符抛 ValueError
- 超出 min/max 范围抛 ValueError
- 未声明的参数名抛 ValueError（防拼写错误）

### 改造现有策略时注意三个既有机制别丢掉

1. **锁存（hysteresis）**：置位与触发分离，`low1 > low2`、`high1 > high2`
2. **单桶单操作**：FSM 锁存字段 `lock_ts / low_acted / high_acted` 维护在 state.fsm dict (stateful, strategy-step-only);
   防桶内反复触发
3. **指标未就绪防御**：`ema_step` 未就绪时返回 `(state, 0.0)`, 策略代码 `if up == 0.0 or dw == 0.0: return 0` 守卫。

## 4. 周期（任意 m/h/d）

**无需改代码**：`--period 90m` / `--grid "period=30m,2h,6h"` 直接可用（桶算法已升级为
本地锚定 epoch 取整，见 04 第 5 节）。要点：

- 格式 `数字+m/h/d`，如 7m/45m/90m/2h/6h/3d/7d（`resolve_period_seconds` 校验）；
- 能整除天长的周期边界对齐钟面（如 2h/6h），否则边界相对钟面每日漂移（如 7m），
  分区始终连续无重叠；
- 周期越大，验证窗内桶数/成交越少（`--min-trades` 会自然过滤），同时确认
  `--warmup-days` 足够让策略自己的指标完成 seed（如 EMA 需 tf1 个桶）；
- 周期是任意 `m/h/d` 字符串，经 `resolve_period_seconds` 解析为秒；不再有周期白名单。

## 5. 调整/新增指标（纯 Python + torch）

**新增指标**（如布林带 / ATR / RSI / 自定义动量）只需在 `evtrade/indicators/<name>.py` 加函数，
**framework 0 改动**，按现有 `ema.py` 的两种形态对齐：

1. **step 增量版**（策略 `step` body 调）: `<name>_step(state, value, ...) -> (state, out)`
   —— state 是 `@dataclass`，in/out 单对象；未就绪时返回 0 占位（策略侧 `if ... == 0.0: return 0` 守卫）。
2. **纯 ndarray 批量参考版**（reconcile 参考 / 测试 / 复盘用，策略不直接调）: `<name>(values, ...) -> ndarray`

示例（假设你要新增一个布林带指标，step 版）:

```python
# evtrade/indicators/band.py (假设新增)
@dataclass
class BandState:
    sma: float
    var: float
    count: int

def band_step(state: BandState, value: float, p: int, k: float) -> tuple[BandState, float, float, float]:
    # ... SMA seed + 递推 ...
    return state, mid, upper, lower
```

```python
# 策略 step 中使用:
state.band, mid, upper, lower = band_step(state.band, bar["c"],
                                          int(params["tf1"]), float(params["k"]))
```

**调整已有指标**（如改 EMA 默认周期）：改策略 `params_spec` 里 `tf1` 默认值，无需改 framework。

> **历史警示已撤销**: 旧版"换指标需同步改内核 step + CUDA 模板"在
> `change 2026-09-09-unify-strategy-contract` + `strategy-step-only` 后**完全作废**
> —— kernel step 与 CUDA 模板已删除（无 numba / 无 CUDA / 无 NVRTC）；
> 指标完全由策略 `step(state, bar, params)` 内部调 `evtrade.indicators/` 的 `*_step` 维护。

- 校验方法：用纯函数版思路写批量重算，对比增量输出（项目内 `indicators/ema.py` 保留 `ema`/`ema_channel`（numpy 批量参考）与 `ema_step`/`ema_channel_step`（增量），互为校验）。

## 6. 其他常见改造点

| 需求 | 改哪里 |
|---|---|
| 多标的回测 | 外层循环 `--code`；或在 bar 流内去过滤并给桶加 code 维度（Aggregator 目前是单标的单实例） |
| 手续费/滑点 | `SimulatedExecutor.trade` 成交价加滑点；`Account.apply` 扣费用；`metrics.summarize` 保持"总资产"口径自动体现 |
| 止损/止盈 | 在 `Engine.on_bars` 里 signal 判定后追加风控检查（拿得到 cur 的 H/L/C 与账户持仓） |
| 输出到文件/数据库 | 替换 `SimulatedExecutor`/`Engine` 中的 `print`；`account.trades` 已是结构化流水 |
| 持仓过夜/周末 gap | 当前模型无处理（信号即成交）；实盘接入时在自定义 Executor 子类层考虑集合竞价与涨跌停 |
| 数据库配置外置 | `DB_URL` 已支持环境变量 `EVTRADE_DB_URL` 覆盖（`core/config.py`，含密码，注意不要提交到公开仓库） |

## 7. 策略展示 hook (2026-09-08 框架去特殊化; 2026-09-09 简化)

框架层**不假定任何指标字段名**; 信号行打印由策略覆写 `format_signal_line` 完成
（`VectorizedStrategy` 默认实现仅打 OHLCV + 信号；`ChannelDeviationStrategy` 实现于 `channel_deviation.py::format_signal_line`）。

| Hook | 签名 | 用途 | 默认实现 |
|---|---|---|---|
| `format_signal_line` | `(ts, sig, info) -> str` | verbose 引擎的信号行打印；**无 positional 指标**，所需字段从 `info` dict 自取 | 仅打 OHLCV + 信号 |

> **2026-09-09 变化**: 删除 `get_extra_bucket_columns` / `get_extra_signal_columns`（旧 bucket_table / per-bar bundle）。
> framework 输出列已简化为 OHLCV + sig（桶表） / `(stime, signal)`（信号轨迹）；
> 策略若需要展示列, 应在 `format_signal_line` 内一次性算（verbose 引擎才打）。
