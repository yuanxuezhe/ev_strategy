## 1. 项目定位

一个**回测 / 实盘统一架构**的量化交易演示框架：

- 数据源：MySQL `evtrade` 库的 `minute_bars` 表（1 分钟原始行情）
- 核心能力：**周期合并**（1m → 任意 `m/h/d` 周期）+ **EMA 通道偏离策略**
- 目标：同一套引擎代码，回测跑历史、实盘接实时，只换"行情源"和"下单器"两个组件

分层（数据 → 合并 → 策略 → 执行）：

```
bar 流 (行情源)  ──yield Bar──▶ Engine
                                 │
                            BarAggregator (周期合并, 独立于策略)
                                 │ on_bars(周期K线集合)
                                 ▼
                       ChannelDeviationStrategy + ema_channel(指标)
                                 │ signal
                                 ▼
                            Executor (模拟/真实下单) → Account (资金持仓)
```

**切换实盘/回测：换 bar 流 + 换 Executor，其余不变。**

## 2. 核心特性

1. **纯增量计算**：周期合并 O(1)/根，EMA 通道 O(1)/桶（`ema_channel_step`），可支撑实盘逐根推送
2. **前开后闭、右端点标注**的合并桶时间戳（与通达信等主流行情软件一致），详见 04 文档
3. **预热机制**：策略起始日之前默认再拉 365 天数据做指标预热（`mark=0`），策略期（`mark=1`）才驱动交易
4. **锁存式策略**：极端偏离置位 → 回撤确认触发，天然带迟滞（hysteresis），避免边界反复触发
5. **单桶单操作**：同一根周期 K 线内每个方向最多一次状态转换，防止桶内 H/L 大幅波动反复打信号
6. **组件解耦**：行情源、合并器、指标、策略、账户、下单器全部独立，可单独替换
7. **基线对比**：回测汇总同时给出"策略总资产"与"不操作基线"，直接看出策略超额盈亏

## 4. 关键默认值（速查）

| 项 | 默认值 | 定义处 |
|---|---|---|
| 数据库 | `mysql+pymysql://EvTrade:***@192.168.10.2:33066/evtrade?charset=utf8mb4`（`EVTRADE_DB_URL` 可覆盖） | `core/config.py::DB_URL` |
| 数据表 | `minute_bars` | `core/config.py::TABLE` |
| K 线周期 | `5m`（任意 `m/h/d` 字符串均可） | `--period` |
| 策略区间 | `20250101 ~ 20260903` | `--start` / `--end` |
| 证券 | `159992.SZ` | `--code` |
| 通道轨 EMA 周期 tf1 | 21 | 策略 `params_spec`（经 `--params "tf1:21"` 传入） |
| 策略阈值 | low1/low2=1.5/1.0，high1/high2=1.5/0.5（百分比） | `--params "low1:1.5;low2:1.0;high1:1.5;high2:0.5"` |
| 期初资金 / 期初持仓 | 200000 元 / 200000 股 | `core/config.py::INIT_CASH` / `INIT_POSITION` |
| 每次交易数量 | 10000 股 | `core/config.py::TRADE_QTY`（`--trade-qty` 覆盖） |
| 预热天数 | 365 天 | `core/data.py::load_bars(warmup_days=365)`（`--warmup-days` 覆盖） |

> `evtrade/strategies/_defaults/<strategy>.json` 存落盘默认参数（`params save` / `params save --from-csv`），
> 单次回测不传 `--params` 自动读；CI/实盘机用 `EVTRADE_DEFAULTS_DIR` 环境变量切换目录（不污染仓库）。
> 仓库内落盘文件须经 `_resolve_params` 校验（类型/范围），且满足各策略硬约束
> （如 `channel_deviation` 必须 `low1 > low2` 且 `high1 > high2`，否则锁存失效）。

## 5. 快速上手

```bash
# 回测 (CPU 后端, 默认 5m 周期)
python -m evtrade backtest --period 5m --start 20250101 --end 20260903 --device cpu

# 换标的 / 换周期 / 调策略参数
python -m evtrade backtest --period 1h --code 513120.SH --params "low1:2;low2:1.2"
```

运行后输出：数据加载进度（`core/data.py::load_bars` 打印）→ 信号行（策略触发时打印完整指标快照）→ 回测盈亏汇总（`core/metrics.py::summarize`）。输出解读见 10 文档。
