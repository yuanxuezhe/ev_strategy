# 06 扩展指南

## 1. 新增行情源(bar 流)

bar 流是**鸭子类型**对象: 只需提供 `.stream() -> Iterator[Bar]` 方法, 无需继承基类。

```python
class LiveStream:
    def __init__(self, code: str): ...

    def stream(self) -> Iterator[Bar]:
        while True:
            tick = ...                      # 从行情 API / websocket 取数
            yield Bar(stime=..., code=self.code, open=..., high=...,
                      low=..., close=..., volume=...)
```

必须遵守的契约:

1. `stime` 为 14 位 `YYYYMMDDHHmmss` 字符串(预热比较、SQL、排序全依赖字符串序)
2. 从旧到新、单调不减(桶合并按顺序推进, 乱序会污染 open/close 与桶切换)
3. 字段类型与 `Bar` 一致(volume 为 int)

实盘组合用"自定义组合 bar 流": 先历史预热(`mark=0` 让策略累积自己的指标状态)再接实时:

```python
class HistThenLive:
    def stream(self):
        yield from load_history_bars(code, start, today, warmup_days=365)  # 历史预热
        yield from live(code)                                              # 接实时
```

实时源额外注意: 断线重连后从最后 stime 续传、去重(同 stime 重复推送会被当成同桶更新,
volume 会重复累加)、收盘后无数据时的阻塞策略。

## 2. 新增/修改策略

**唯一契约**: 继承 `VectorizedStrategy`(`evtrade/strategies/vectorized_base.py`),
实现 `step(self, state, bar, params) -> (state, int)` 一个方法。
无状态策略覆写 `init_state(self, params) -> None`;
stateful 策略覆写返 `@dataclass`。

```python
from dataclasses import dataclass
from evtrade.strategies.vectorized_base import (
    VectorizedStrategy, register_strategy,
)
from evtrade.indicators import EMAState, ema_step

@dataclass
class MyState:
    ema: EMAState = None  # dataclass field

@register_strategy("my_strategy")
class MyStrategy(VectorizedStrategy):
    params_spec = {
        "p0": {"default": 21, "type": int, "min": 2, "max": 1000},
        "p1": {"default": 1.5, "type": float, "min": 0.0, "max": 100.0},
    }

    def init_state(self, params):
        return MyState(ema=EMAState())

    def step(self, state, bar, params):
        if bar["mark"] == 0:
            return state, 0
        p0 = int(params["p0"])
        state.ema, ema = ema_step(state.ema, float(bar["c"]), p0)
        # ... 算 sig, 返 (state, sig) ...
        return state, sig
```

- `state` 是上一调用返回的 state, 跨调用由 **engine 持有**(策略无 instance attr)
- `bar` 契约: `{"ts", "o", "h", "l", "c", "v", "mark"}`(单桶)
- 返回元组 `(state, sig)`, sig ∈ {-1, 0, 1}
- `mark == 0`(预热)直接返 `(state, 0)`; framework 不做兜底

**engine 循环调 step**: `VectorizedEngine._compute_signals` 与 `Engine.on_bars`
都循环调 `strategy.step(state, bar, params)`, state 由 engine 持有。
两条路径走同一份 step 算法, 信号 bitwise 一致(对账测试锁定)。

完整范式见 [04-策略](04-策略.md) 三个内置策略(`channel_deviation` / `ma_crossover` / `filtered_mr`)。

### 改造现有策略时注意三个既有机制别丢掉

1. **锁存(hysteresis)**: 置位与触发分离, `low1 > low2`、`high1 > high2`
2. **单桶单操作**: FSM 锁存字段 `lock_ts / low_acted / high_acted` 维护在 `state.fsm` dict;
   防桶内反复触发
3. **指标未就绪防御**: `ema_step` 未就绪时返回 `(state, 0.0)`, 策略代码
   `if up == 0.0 or dw == 0.0: return 0` 守卫

### 可选 `batched_step` 类方法 hook(GPU 加速)

如果策略是纯 EMA 增量、无 FSM(范式如 `ma_crossover`), 可实现
`batched_step(cls, state, bars, params, *, n_combos, n_bars)` opt-in hook,
让 sweep 在 `device != "cpu" + len(combos) ≥ 32 + gpu_available + 真覆写 hook` 时
走 batched 路径(详见 [07-PyTorch与性能](07-PyTorch与性能.md))。

## 3. 新增数据源(非鸭子流, 接 load_bars 分支)

如果新数据源(如 Tushare / AkShare / CSV / Parquet)需要接 `load_bars` 路径:

1. 实现 `fetch_xxx()` 返回与 `load_bars` 同构的 numpy 数组字典
   `{stime:int64, open/high/low/close/volume:float64}`
2. 在 `load_bars` 里加分支(例如 `if source == 'tushare': return fetch_tushare(...)`)
3. CLI 加 `--data-source` 参数

实盘接入 = 直接实现 `.stream()` 对象(见 §1), 绕过 `load_bars`。

## 4. 周期(任意 m/h/d)

**无需改代码**: `--period 90m` / `--grid "period=30m,2h,6h"` 直接可用
(桶算法已升级为本地锚定 epoch 取整, 详见 [02-数据与桶 §任意周期支持](02-数据与桶.md))。

要点:

- 格式 `数字+m/h/d`, 如 7m / 45m / 90m / 2h / 6h / 3d / 7d(`resolve_period_seconds` 校验)
- 能整除天长的周期边界对齐钟面(如 2h / 6h); 否则边界相对钟面每日漂移(如 7m),
  分区始终连续无重叠
- 周期越大, 验证窗内桶数 / 成交越少, 同时确认预热足够让策略自己的指标完成 seed
  (如 EMA 需 tf1 个桶)
- 周期是任意 `m/h/d` 字符串, 经 `resolve_period_seconds` 解析为秒; **不再有周期白名单**

## 5. 调整/新增指标

> **新增指标(框架 0 改动)**: 在 `evtrade/indicators/<name>.py` 加函数, 按现有 `ema.py` 的三种形态对齐:

1. **step 增量版**(策略 `step` body 调): `<name>_step(state, value, ...) -> (state, out)`
   —— state 是 `@dataclass`, in/out 单对象; 未就绪时返回 0 占位(策略侧 `if ... == 0.0: return 0` 守卫)
2. **numpy 批量参考版**(reconcile 参考 / 测试 / 复盘用, 策略不直接调): `<name>(values, ...) -> ndarray`
3. **torch 批量版**(batched_step hook 内部用, opt-in): `<name>_torch(values: Tensor[T], ...) -> Tensor[T]`,
   float64 与 numpy 版 bitwise 一致

示例(假设新增一个布林带指标 step 版):

```python
# evtrade/indicators/band.py (假设新增)
@dataclass
class BandState:
    sma: float
    var: float
    count: int

def band_step(state: BandState, value: float, p: int, k: float
             ) -> tuple[BandState, float, float, float]:
    # ... SMA seed + 递推 ...
    return state, mid, upper, lower

# 策略 step 中使用:
state.band, mid, upper, lower = band_step(state.band, bar["c"],
                                          int(params["tf1"]), float(params["k"]))
```

**调整已有指标**(如改 EMA 默认周期): 改策略 `params_spec` 里 `tf1` 默认值, 无需改 framework。

校验方法: 用纯函数版思路写批量重算, 对比增量输出(项目内 `indicators/ema.py` 保留
`ema` / `ema_channel`(numpy 批量参考)与 `ema_step` / `ema_channel_step`(增量), 互为校验)。

## 6. 实盘接入

> 2026-09-13 后 framework **不提供 `Executor` 基类**(已从 `evtrade/execution/` 下线)。
> 实盘接入 = 自供一个 `.stream()` 对象 + 在策略 `step` 内自写撮合与记账。

```python
class MyLiveStrategy(VectorizedStrategy):
    def step(self, state, bar, params):
        # ... 算法 (与回测完全相同)
        if sig != 0:
            # 调真实券商 API
            order = broker.place_order(sig, bar["c"], bar["ts"])
            # 等待成交回报 (此处简化, 实际需要回报回调)
            actual_qty, actual_price = order.fill_qty, order.fill_price
            state.cash += -actual_qty * actual_price if sig > 0 else actual_qty * actual_price
            state.position += actual_qty if sig > 0 else -actual_qty
            state.trades.append({...})
        return state, sig
```

实盘与回测用**同一份策略代码**(仅 `step` 内撮合调用替换), framework 不需任何改动。
撮合数学模板见 [04-策略 §2](04-策略.md)。

## 7. 策略展示 hook

| Hook | 签名 | 用途 | 默认实现 |
|---|---|---|---|
| `format_signal_line` | `(ts, sig, info) -> str` | verbose 引擎的信号行打印; **无 positional 指标**, 所需字段从 `info` dict 自取 | 仅打 OHLCV + 信号 |

约定(`openspec/changes/enrich-signal-line-context`): 当 `sig != 0` 时 hook 输出 MUST 含
**方向词 (BUY/SELL) + 价格 + `o=`/`h=`/`l=`/`c=` 4 个字段名**; `info.get(...)` 守卫防 KeyError。
锁定测试: `tests/test_format_signal_line_enrich.py`。

## 8. 其他常见改造点

| 需求 | 改哪里 |
|---|---|
| 多标的回测 | 外层循环 `--code`; 或在 bar 流内去过滤并给桶加 code 维度(Aggregator 目前是单标的单实例) |
| 手续费/滑点 | 策略 `step` 内撮合数学加滑点 + 扣费用(framework 不再做) |
| 止损/止盈 | 策略 `step` 内 signal 判定后追加风控检查(拿得到 cur 的 H/L/C 与账户持仓) |
| 输出到文件/数据库 | 在策略 `step` 内写 `state.trades` 已结构化; 输出格式化由策略自提供 hook |
| 持仓过夜/周末 gap | 策略自处理(框架无此概念); 实盘接入时在策略 step 内考虑集合竞价与涨跌停 |
| 数据库配置外置 | `EVTRADE_DB_URL` / `EVTRADE_TABLE` 环境变量覆盖(`data.DB_URL` 默认值含密码, **不要提交到公开仓库**) |
